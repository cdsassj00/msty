## Context Scout란

큰 프로젝트 폴더에서 "로그인이 가끔 실패해요"라고만 물으면, 모델은 어느 파일부터 봐야 할지 모릅니다. **Context Scout**는 프롬프트가 전송되기 전에 작업 공간을 훑어 관련 있을 만한 파일을 찾고, 작업 요약(task brief)을 만들고, 고른 맥락을 모델 입력에 붙여 주는 기능입니다.

답의 품질이 저장소나 작업 공간의 맥락에 달려 있고, Go가 더 나은 근거에서 출발하기를 바랄 때 씁니다.

## 쓸 때와 건너뛸 때

| 쓰면 좋은 경우 | 건너뛰는 경우 |
|---|---|
| 버그 수정에서 문제가 생긴 경로를 찾아야 할 때 | 작업 공간 맥락이 필요 없는 단순한 질문 |
| 코드를 고치기 전에 구현 계획을 세울 때 | 작업 공간 폴더가 없는 대화 |
| 코드 검토나 회귀 점검 | 에이전트 대화 |
| 파일을 손으로 고르기 느린 큰 저장소 | 슬래시 명령 |
| 동작은 말하지만 정확한 파일은 모르는 프롬프트 | 필요한 파일이 이미 맥락에 있는 후속 질문 |

Scout는 작업 공간을 아는 작업의 첫 턴을 좋게 만들기 위한 것입니다. 모든 메시지에 돌리는 기능이 아닙니다.

## 쓸 수 있는 조건

다음을 모두 만족해야 합니다.

- 현재 대화에 작업 공간 폴더가 있다.
- 에이전트 대화가 아니다.
- 프롬프트가 슬래시 명령이 아니다.
- 제공업체와 모델을 쓸 수 있다.

작업 공간이 선택되어 있지 않으면 Scout 컨트롤이 폴더를 고르라고 안내합니다.

## 사용 순서

1. 작업 공간이 있는 대화를 고릅니다.
2. 대화 입력창 근처의 Context Scout 컨트롤을 엽니다.
3. **Scout before send**를 켭니다.
4. 모드와 깊이를 고릅니다.
5. 필요하면 **Review before send**를 켭니다.
6. 프롬프트를 보냅니다.

Scout가 붙은 전송이 성공하면 Go는 다음 턴에서 Scout를 자동으로 끕니다. 나중에 새로 탐색이 필요한 프롬프트가 있으면 다시 켭니다.

## 세 가지 모드

모드는 의도에 맞춰 고릅니다. 모드에 따라 Scout가 파일의 우선순위를 매기는 방식과 작업 요약의 틀이 달라집니다.

| 모드 | 찾는 것 |
|---|---|
| **Fix** | 버그를 설명하거나, 재현하거나, 고치거나, 검증하는 데 관련 있을 파일 |
| **Plan** | 구현 전에 알아야 할 진입점, 계약(인터페이스), 기존 패턴 |
| **Review** | 바뀌었거나 위험한 경로, 테스트, 공유 계약, 회귀 위험 |

## 세 가지 깊이

깊이는 탐색을 얼마나 넓게 할지 정합니다.

| 깊이 | 범위 | 쓰는 경우 |
|---|---|---|
| **Lean** | 가장 유력한 출발점만 좁게 | 작업 위치를 대략 알 때 |
| **Balanced** | 기본값. 관련 있을 파일을 고르게 | 대부분의 작업 공간 작업 |
| **Deep** | 호출 지점, 계약, 테스트, 지도까지 넓게 | 요청이 여러 모듈에 걸치거나 문제 경로가 불분명할 때 |

## Scout가 붙여 주는 것

- 작업 요약
- 먼저 볼 파일 제안
- 그 파일을 고른 이유
- 코드 지도와 심볼 요약
- 프로젝트 지도 항목
- 모델 사전 조사를 쓴 경우: 모델이 만든 발견 사항, 접근 방법 메모, 위험, 남은 질문

문서는 Scout의 결과를 강한 출발점으로 보되 넘지 못할 경계로 삼지는 말라고 합니다. Go는 파일을 고치기 전에 여전히 파일을 직접 읽어 사실을 확인해야 합니다.

## 두 겹의 탐색

| 층 | 하는 일 |
|---|---|
| **Native scan** | 작업 공간에서 관련 파일을 찾고 파일·코드 지도 맥락을 만듭니다 |
| **Model preflight** | 선택한 모델로 작업 요약을 다듬고 더 나은 파일 단서를 제안합니다 |

모델 사전 조사를 쓸 수 없거나, 실패하거나, 멈추면 Scout는 Native scan 결과로 넘어갑니다. 그래서 전송은 쓸 만한 맥락을 붙인 채 계속 진행됩니다.

## 전용 모델 배정

**Settings > Model Assignments > Context Scout**에서 Scout 전용 모델을 정할 수 있습니다. 배정해 두면 Scout는 사전 조사에 그 모델을 씁니다. 배정된 제공업체를 쓸 수 없으면 가능한 경우 현재 대화 모델로 넘어갑니다.

전용 모델이 유용한 경우는 세 가지입니다.

- 보내기 전 탐색에는 더 싸거나 빠른 모델을 쓰고 싶을 때
- 주 대화 모델은 실행에만 집중시키고 싶을 때
- 여러 대화에서 탐색 동작을 같게 유지하고 싶을 때

## 보내기 전 검토

**Review before send**를 켜면 프롬프트가 나가기 전에 Scout의 결과를 확인하고 고칠 수 있습니다. 검토 서랍에서 할 수 있는 일은 다음과 같습니다.

- 만들어진 작업 요약 확인
- 선택된 파일 검토
- 파일 맥락을 넣거나 빼기
- 보내기 전에 프롬프트 고치기
- Scout가 붙은 전송 취소

위험이 큰 변경, 넓은 탐색, 맥락 선택이 중요한 작업에 씁니다.

## 지원 언어

Scout가 현재 인식하는 언어군은 다섯 가지입니다.

- TypeScript
- JavaScript
- Python
- Go
- Rust

다른 종류의 파일도 프로젝트 지도나 주변 맥락을 통해 나타날 수 있지만, 본격적인 스캔 지원은 위 언어에 한정됩니다. 문서 폴더처럼 코드가 아닌 작업 공간에서 Scout가 얼마나 도움이 되는지는 공식 문서에 설명이 없습니다.

## Data Protection과 함께 쓸 때

Data Protection 미리보기가 켜져 있으면, Scout는 보호 처리된 프롬프트 경로에서 탐색을 준비합니다. 민감한 내용의 처리가 전송 흐름과 어긋나지 않게 하기 위해서입니다.

민감한 데이터를 다루는 작업이라면 실제 업무에 쓰기 전에 위험이 낮은 프롬프트로 두 기능의 조합을 먼저 검증하라고 문서는 권합니다.

## 문제 해결

### Scout를 쓸 수 없을 때

1. 대화에 작업 공간 폴더가 있는지 확인합니다.
2. 에이전트 대화 안이 아닌지 확인합니다.
3. 프롬프트가 슬래시 명령이 아닌지 확인합니다.
4. 제공업체와 모델 설정이 동작하는지 확인합니다.
5. Scout에 배정한 모델의 제공업체가 보이고 사용 가능한지 확인합니다.

### Scout가 찾은 맥락이 약할 때

1. `Lean`에서 `Balanced`나 `Deep`으로 바꿉니다.
2. 프롬프트에 업무 용어, 파일 이름, 기대하는 동작을 더 넣어 다시 씁니다.
3. **Review before send**를 켜고 관련 없는 결과를 뺍니다.
4. 전송한 뒤 주 대화에서 Go에게 다른 파일도 살펴보라고 요청합니다.
