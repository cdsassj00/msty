## 감사 로그란

감사 로그는 Enterprise 계정에서 일어난 중요한 사용자·팀 관리 행위를 기록한 것입니다. 누가 사용자를 넣고 뺐는지, 누가 팀 설정을 바꿨는지 같은 관리 차원의 변화를 나중에 되짚어 볼 수 있게 합니다.

공식 문서의 이 항목은 짧습니다. 이 글도 문서가 밝힌 범위 안에서만 설명하고, 문서에 없는 내용은 없다고 적습니다.

## 기본 사항

| 항목 | 내용 |
|---|---|
| 요금제 | Enterprise 요금제에서 제공 |
| 볼 수 있는 사람 | Owner와 Admin |
| 보는 곳 | **Teams > Audit Trail** |
| 기록 대상 | 중요한 사용자·팀 관리 수준의 행위 |

요금 비교표에서도 "Audit Log"는 Teams 열에만 표시되어 있습니다. 역할에 대한 설명은 [사용자 관리](/guide/enterprise-users/)에 있습니다.

## 기록하는 것

문서는 "중요한 사용자·팀 관리 수준의 행위"를 추적한다고만 적었습니다. 기록되는 사건의 구체적인 목록은 문서에 없습니다.

다른 문서 항목에 나오는 관리 행위는 다음과 같으며, 이런 종류가 대상이라고 볼 수 있습니다. 다만 각각이 실제로 기록되는지는 화면에서 확인해야 합니다.

- 사용자 초대, 수정, 삭제
- 역할 변경 (Admin으로 올리기, User로 내리기)
- 사용자 정지와 해제
- 팀 만들기와 설정 변경
- 사용자의 팀 배정 변경

## 기록하지 않는 것

이 부분이 가장 중요합니다. 문서는 감사 로그의 범위 밖을 분명히 적었습니다.

감사 로그는 다음과 같은 사용자 활동을 다루지 않습니다.

- 대화
- Knowledge Stack 사용
- 그 밖의 앱 안에서의 행동

문서는 Msty에 이런 정보를 잡아내는 원격 측정이 없다고 밝힙니다.

정리하면 이렇습니다.

| 질문 | 감사 로그로 알 수 있는가 |
|---|---|
| 누가 이 사용자를 Admin으로 올렸는가 | 관리 행위이므로 대상 |
| 누가 이 팀에 온라인 제공업체를 열어 줬는가 | 관리 행위이므로 대상 |
| 김 대리가 어제 무엇을 물어봤는가 | 알 수 없음 |
| 누가 이 문서를 Knowledge Stack에 넣었는가 | 알 수 없음 |
| 어느 팀이 어떤 모델을 얼마나 썼는가 | 알 수 없음 |

이것은 Msty Studio의 설계와 맞닿아 있습니다. 대화가 사용자 기기에만 있고 Msty 서버로 가지 않으므로, 중앙에서 대화 내용을 기록할 길이 없습니다. 사용자 입장에서는 사생활 보호이고, 감사 담당자 입장에서는 한계입니다.

## 조직의 요구와 맞는지 따져 보기

감사 요구는 조직마다 다릅니다. 도입 전에 어느 쪽인지 확인하세요.

| 조직의 요구 | Studio 감사 로그로 충족되는가 |
|---|---|
| 계정과 권한 변경 이력을 남겨야 한다 | 대상 범위에 듭니다 |
| 직원이 AI에 입력한 내용을 보관해야 한다 | 충족되지 않습니다 |
| 모델별·앱별 사용량을 봐야 한다 | 충족되지 않습니다 |

둘째와 셋째가 필요하다면 다른 수단이 있어야 합니다. 모델 요청이 지나는 길목에서 사용량을 보는 제품은 Nexus입니다. Nexus는 앱별, 제공업체별 요청 수와 사용량을 보여 주며, Enterprise 요금제에 팀·사용자 로깅이 들어 있습니다. 다만 Nexus 문서도 진단 기록에 프롬프트와 응답을 넣지 않는다고 밝힙니다. [Msty Nexus 자세히 보기](/guide/product-nexus/)를 보세요.

입력 내용의 보관이 법적 의무인 조직이라면, 이 요구를 어떻게 충족할지 Msty와 도입 전에 직접 논의해야 합니다.

## 저장 위치

저장 위치에 대해서는 공식 문서의 두 항목이 서로 다르게 적고 있습니다.

| 문서 항목 | 적힌 내용 |
|---|---|
| Audit Log | 로그는 각 사용자의 기기에 로컬로 저장됩니다. 사용자, 또는 그 로컬 설치에 접근할 수 있는 회사 관리자가 사용자의 로컬 Msty Studio 설치에서 볼 수 있습니다 |
| Enterprise Overview | Msty는 사용자, 팀, 감사 로그 데이터를 자사 서버에 저장합니다 |

두 설명이 서로 다른 종류의 기록을 가리키는 것일 수도 있고, 한쪽이 예전 내용일 수도 있습니다. 문서만으로는 판단할 수 없습니다.

이 차이는 실무에서 중요합니다.

- 로그가 사용자 기기에만 있다면, 기기를 잃거나 초기화하면 로그도 사라집니다. 중앙에서 모아 보려면 따로 수집해야 합니다.
- 로그가 Msty 서버에 있다면, 저장 지역과 보관 기간이 검토 대상이 됩니다.

감사 로그가 도입 조건인 조직은 Msty에 다음을 서면으로 확인하기를 권합니다.

1. 감사 로그가 저장되는 정확한 위치
2. 기록되는 사건의 전체 목록
3. 보관 기간
4. 내보내기 방법과 형식
5. 로그의 변경·삭제를 막는 장치가 있는지

## 보는 방법

1. Owner 또는 Admin 계정으로 로그인합니다.
2. **Teams**로 갑니다.
3. **Audit Trail** 화면을 엽니다.

화면에 어떤 열이 있는지, 기간이나 사용자로 걸러 볼 수 있는지, 파일로 내보낼 수 있는지는 문서에 적혀 있지 않습니다. 문서에는 화면 그림 한 장만 실려 있습니다.

## 이름이 비슷한 기능

Msty Studio에는 "로그"라는 이름이 붙은 기능이 둘 있어 헷갈리기 쉽습니다.

| 기능 | 위치 | 내용 | 요금제 |
|---|---|---|---|
| Audit Log | **Teams > Audit Trail** | 사용자·팀 관리 행위 | Enterprise |
| Log Viewer | Settings의 Desktop Extras | 앱의 동작과 오류 기록. 문제 해결용 | 문서에 조건 없음 |

Log Viewer는 모델이 응답하지 않거나 도구 실행이 실패할 때 원인을 찾는 데 쓰는 기술 기록입니다. 감사 용도가 아닙니다. [설정 화면 둘러보기](/guide/settings-overview/)를 보세요.

## 감사 로그를 보완하는 방법

문서의 범위를 넘는 내용이지만, 감사 로그가 다루지 않는 부분을 조직이 채우는 일반적인 방법을 적습니다.

- **정책으로 막기**: 기록할 수 없는 것은 처음부터 못 하게 합니다. 민감한 자료를 다루는 팀에는 온라인 제공업체와 외부 연결 기능을 열지 않습니다. [팀 관리](/guide/enterprise-teams/)를 보세요.
- **길목에서 보기**: 모델 요청이 Nexus 같은 게이트웨이를 지나게 하면 사용량과 활동을 한곳에서 봅니다.
- **제공업체 쪽 기록**: 온라인 모델을 회사 계약으로 쓴다면 그 제공업체의 사용 기록과 감사 기능을 활용합니다.
- **기기 관리**: 대화가 기기에 있으므로, 기기 암호화와 회수 절차가 곧 대화 자료의 보호 수단입니다.
- **사용 규정**: 무엇을 입력해도 되고 무엇은 안 되는지 직원에게 문서로 알립니다.

전체 보안 설명과 인증 현황은 [보안과 거버넌스](/guide/security-governance/)에 모았습니다.
