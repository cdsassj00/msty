## 무엇을 정하는 설정인가

Msty Studio에서는 프로젝트나 페르소나에 사용자 지정 프롬프트를 넣을 수 있습니다. 이때 이미 있는 시스템 프롬프트와 내 프롬프트를 **어떻게 합칠지** 정하는 것이 System Prompt Modes입니다. 방식은 세 가지입니다.

- **Prepend** — 내 프롬프트를 앞에 붙입니다.
- **Replace** — 내 프롬프트로 바꿉니다.
- **Append** — 내 프롬프트를 뒤에 붙입니다.

어떤 방식을 쓰느냐에 따라 모델이 행동과 말투를 받아들이는 방식이 달라집니다.

## 예시로 보는 세 가지 방식

공식 문서의 예시를 그대로 씁니다.

- 내 프롬프트: "You are a pirate who speaks like a pirate." (해적처럼 말하는 해적입니다)
- 시스템 프롬프트: "You are a helpful assistant." (도움이 되는 조수입니다)

| 방식 | 모델에 전달되는 최종 프롬프트 |
|---|---|
| **Prepend** | "You are a pirate who speaks like a pirate. You are a helpful assistant." |
| **Replace** | "You are a pirate who speaks like a pirate." |
| **Append** | "You are a helpful assistant. You are a pirate who speaks like a pirate." |

## Prepend — 내 지시를 앞에

내 프롬프트가 시스템 프롬프트 **앞에** 놓입니다.

| 구분 | 내용 |
|---|---|
| 장점 | 내 지시에 우선순위가 생깁니다. 말투, 문체, 특정 역할을 먼저 정하는 데 좋습니다. 기본 시스템 프롬프트의 안전·도움 규칙은 유지됩니다 |
| 단점 | 두 프롬프트의 어조가 다르면 충돌할 수 있습니다. 내 지시가 모델의 기본 동작을 완전히 덮지는 못할 수 있습니다 |
| 맞는 경우 | 행동이나 역할을 강하게 이끌되, 도움이 되는 기본 바탕은 남기고 싶을 때 |

## Replace — 내 지시만

내 프롬프트가 시스템 프롬프트를 **완전히 대체**합니다.

| 구분 | 내용 |
|---|---|
| 장점 | 모델의 동작을 온전히 통제합니다. 맞춤 페르소나, 창작용 캐릭터, 특화된 작업 흐름에 알맞습니다 |
| 단점 | 기존 프롬프트에 있던 동작(안전, 중립성, 도움 등)이 모두 사라집니다. 문제나 원치 않는 답을 피하려면 프롬프트를 신중하게 써야 합니다 |
| 맞는 경우 | 모델의 역할과 말투를 처음부터 끝까지 직접 정의하고 싶을 때 |

## Append — 내 지시를 뒤에

내 프롬프트가 시스템 프롬프트 **뒤에** 놓입니다.

| 구분 | 내용 |
|---|---|
| 장점 | 모델의 기본 동작을 보존합니다. 어조 조정이나 특정 응답 형식 같은 가벼운 추가에 좋습니다. 시스템 규칙과 충돌할 가능성이 낮습니다 |
| 단점 | 우선순위가 낮아 내 지시가 덮이거나 무시될 수 있습니다. 동작을 크게 바꾸는 데는 맞지 않습니다 |
| 맞는 경우 | 핵심 동작은 그대로 두고 답을 보완하거나 다듬고 싶을 때 |

## 한눈에 비교

| 방식 | 동작 | 충돌 위험 | 통제 수준 | 시스템 프롬프트 유지 |
|---|---|---|---|---|
| **Prepend** | 내 프롬프트를 시스템 프롬프트 앞에 추가 | 중간 | 중간 | 예 |
| **Replace** | 내 프롬프트만 사용 | 낮음 | 높음 | 아니요 |
| **Append** | 내 프롬프트를 시스템 프롬프트 뒤에 추가 | 낮음 | 낮음~중간 | 예 |

고르는 기준을 정리하면 이렇습니다. "항상 표로 답해 주세요" 같은 가벼운 형식 요청은 Append, 특정 역할을 분명히 맡기되 기본 규칙은 남기려면 Prepend, 역할을 통째로 새로 정의하려면 Replace입니다.

## 프로젝트 계층에서의 동작

프로젝트 폴더 안에 하위 프로젝트, 그 안에 또 하위 프로젝트가 있는 구조에서는 Prepend와 Append를 이용해 프롬프트를 사슬처럼 이어 붙일 수 있습니다.

**기본값은 Replace입니다.** 즉 하위 프로젝트는 따로 설정하지 않으면 상위 프로젝트의 시스템 프롬프트를 무시합니다. 상위의 프롬프트를 이어받으려면 하위 프로젝트의 설정에서 Prepend나 Append를 골라야 합니다.

공식 문서의 예입니다. 상위 프로젝트의 시스템 프롬프트가 "I'm the parent."이고, 그 아래 하위 프로젝트의 시스템 프롬프트가 "I'm the child."라고 합시다. 하위 프로젝트 설정의 **System Prompt Attach Mode**에 따라 새 대화의 시스템 프롬프트는 이렇게 됩니다.

| **System Prompt Attach Mode** | 새 대화의 시스템 프롬프트 |
|---|---|
| **Replace** (기본값) | "I'm the child." |
| **Prepend** | "I'm the child. I'm the parent." |
| **Append** | "I'm the parent. I'm the child." |

### 업무에 적용하는 예

상위 프로젝트 "교육 사업"에 "모든 답은 합니다체로, 공문서 용어를 씁니다"라는 프롬프트를 두고, 하위 프로젝트 "수강생 안내문"에 "독자는 60대 이상 수강생입니다. 쉬운 말로 씁니다"를 둡니다. 하위 프로젝트를 Append로 설정하면 두 지시가 모두 적용됩니다. 기본값인 Replace로 두면 하위 프로젝트의 지시만 남고 상위의 문체 규칙은 적용되지 않습니다.

상위 프로젝트에 공통 규칙을 적어 두었는데 하위 프로젝트 대화에서 지켜지지 않는다면, 먼저 **System Prompt Attach Mode**가 Replace로 남아 있지 않은지 확인하세요.
