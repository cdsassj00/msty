## Tasks란

**Tasks**는 반복되는 일을 일정이나 트리거 주기에 맞춰 자동으로 실행합니다. 예측할 수 있는 운영 업무, 알림, 감시 반복에 가장 잘 맞습니다.

문서는 최근의 안정성 개선으로 Task와 오래 걸리는 프롬프트 작업이 규모가 큰 여러 단계 작업에서 더 잘 버틴다고 적습니다.

사이드바의 **Tasks**에서 엽니다.

## 네 가지 유형

| 유형 | 하는 일 |
|---|---|
| `Prompt` | 정해 둔 프롬프트를 실행합니다 |
| `Reminder` | 알림을 보냅니다 |
| `Watcher` | 대상을 지켜보고 변화를 알립니다 |
| 예약 `Playbook` 실행 | [Playbook](/guide/go-playbooks/)을 일정에 맞춰 돌립니다 |

원하는 결과에 맞는 가장 단순한 유형을 고릅니다. 단순한 유형일수록 동작을 이해하기 쉽고, 조용히 실패할 가능성이 낮습니다.

예를 들어(필자가 든 예입니다) "매주 금요일 오후 4시에 주간 보고 마감 알림"은 `Reminder`로 충분합니다. "매일 아침 공지 폴더에 새 파일이 생겼는지 보고 요약"은 `Watcher`가 맞습니다.

표의 설명 가운데 `Prompt`와 `Watcher`의 풀이는 유형 이름과 문서의 다른 절을 바탕으로 정리한 것입니다. 문서는 유형 이름만 나열합니다.

## 알림(Reminder)의 세 가지 모드

| 모드 | 동작 | 쓰는 경우 |
|---|---|---|
| `Plain` | 알림 문구를 그대로 보냅니다 | 예측 가능한 전달이 필요할 때. 여기서 시작합니다 |
| `Source` | 알림을 쓰기 전에 원본에서 맥락을 가져옵니다 | 최신 자료를 반영해야 할 때 |
| `Agent` | 모델과 도구의 도움을 받아 알림을 만듭니다 | 종합이나 도구 사용이 필요할 때 |

모드는 필요할 때만 복잡한 쪽으로 올립니다. 그래야 동작이 일정하고 문제를 찾기 쉽습니다.

## 일정 트리거

| 트리거 | 뜻 |
|---|---|
| `Once` | 한 번 실행 |
| `Cron` | cron 표현식으로 반복 실행 |

운영용 Task라면 왜 이 일정인지를 Task 설명에 적어 둡니다. 담당자도 이름이나 설명에 넣습니다. 그래야 오래된 자동화를 자신 있게 검토하고 폐기할 수 있습니다.

cron 표현식은 익숙하지 않은 사람에게 읽기 어렵습니다. 문서는 cron 일정을 사람이 읽을 수 있는 말로 설명에 풀어 적으라고 권합니다. 예를 들어 `0 9 * * 1`이라면 설명에 "매주 월요일 오전 9시"라고 적는 식입니다(표현식 예는 필자가 든 것입니다).

Go가 지원하는 cron 문법의 세부 범위와 기준 시간대는 공식 문서에 설명이 없습니다.

## 결과를 보낼 곳

Task의 출력은 다음으로 보낼 수 있습니다.

| 목적지 | 설명 |
|---|---|
| 앱 안 | Go 화면 안에서 받습니다 |
| 데스크톱 알림 | 운영체제 알림으로 받습니다 |
| 채널 프리셋 | [채널](/guide/go-channels/)에서 만든 프리셋으로 보냅니다 |
| MCP 도구 | 연결된 MCP 도구로 보냅니다 |

채널과 MCP 목적지는 현재 설정과 대조해 검증됩니다. 영향이 큰 출력은 누가 받는지, 누가 책임지는지 분명히 보이는 목적지로 보내라고 문서는 권합니다.

## 원본을 읽는 Task

Watcher와 원본 기반 알림은 변경 내용을 요약하고 조치가 필요한 변화를 뽑아낼 수 있습니다.

기준은 좁게 잡습니다. 감시 범위가 넓으면 소음이 많아집니다. 좁게 시작하고, 빠뜨리는 것이 확인될 때만 넓힙니다.

## Pulse 새로 고침 Task

[Pulse](/guide/go-pulse/)를 켜면 Go가 `Refresh Pulse`라는 이름의 잠긴 시스템 관리형 Task를 만듭니다. 30분마다 브리핑을 새로 고칩니다.

- Pulse를 켜기 전에 Pulse 모델을 먼저 정합니다.
- 이 Task를 일반 사용자 자동화처럼 다루지 않습니다.
- Pulse를 끄면 이 Task는 일시 정지됩니다.
- Pulse 카드가 오래되어 보이면 Pulse 버튼이나 서랍에서 직접 새로 고칩니다.

Tasks 목록에 내가 만들지 않은 `Refresh Pulse`가 보여도 이상이 아닙니다.

## 배경 작업용 모델

**Settings > Model Assignments**에서 작업별 모델을 배정할 수 있습니다. 요약이나 제목 만들기 같은 배경 기능을 대화용 모델과 다른 모델로 보내, 비용과 속도를 조절하는 용도입니다.

자주 도는 일정이라면 전용 배경 모델이 비용을 눈에 띄게 줄일 수 있다고 문서는 설명합니다. 배정 대상 목록은 [모델 제공업체 설정](/guide/go-model-providers/)에 있습니다.

## Goal 화면 표시

목표 중심 작업에서는 화면을 덜 차지하는 compact Goal UI 모드를 쓸 수 있습니다. 전송 버튼 근처로 작게 접혀, 오래 걸리는 작업을 켜 둔 채 대화 화면을 넓게 쓸 수 있습니다.

## 도입 순서

1. 앱 안 전달로 먼저 검증합니다.
2. 출력 형식이 안정되면 채널이나 도구 목적지로 옮깁니다.
3. Task를 고친 뒤에는 수동으로 한 번 실행합니다.
4. Task 하나에는 목적 하나만 둡니다.

문서는 수동 실행을 자동화의 출시 전 점검으로 보라고 합니다. 형식이나 경로가 틀어진 것을 퍼지기 전에 잡아냅니다.

## 운영 요령

- 한 번 쓰고 마는 목적지 값보다 채널 프리셋을 씁니다.
- cron 일정은 설명에 읽기 쉽게 적습니다.
- 오래된 Task는 불분명한 채로 켜 두지 말고 보관하거나 끕니다.
- 켜져 있는 Task 목록을 정기적으로 검토합니다.

## 다른 기능과 연결되는 지점

- [Memory Bank](/guide/go-memory-bank/)의 Memory Pack을 예약 작업에 붙일 수 있습니다.
- [Extensions](/guide/go-extensions/)는 Task를 구성 요소로 제공하거나, 자동 Task 실행을 일으키는 새 트리거 원천을 더할 수 있습니다.
- Pulse는 예약 작업과 최근의 전달 실패를 살펴 카드로 알려 줍니다.

## 알아 둘 점

- Go 앱이 꺼져 있거나 컴퓨터가 잠자기 상태일 때 예약된 Task가 어떻게 되는지는 공식 문서에 설명이 없습니다.
- 실패한 Task를 자동으로 다시 시도하는지도 문서에 설명이 없습니다.
