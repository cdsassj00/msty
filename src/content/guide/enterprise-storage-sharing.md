## 공유가 작동하는 방식

Msty Studio는 데이터를 각 사용자의 기기에 둡니다. 그래서 한 사람이 만든 프롬프트나 Knowledge Stack을 다른 사람이 쓰려면 그것을 주고받을 장소가 필요합니다.

Enterprise 요금제에서는 그 장소를 회사가 직접 마련합니다. 회사가 가진 S3 호환 저장소를 Msty Studio에 등록하고, 팀원은 그 저장소에 자원을 올리고 내려받습니다. 공식 문서는 Msty가 이 저장소와 그 안의 데이터에 접근할 수 없고, 공유 자원을 Msty 서버에 저장하지 않는다고 밝힙니다.

순서를 한 줄로 쓰면 이렇습니다.

저장소 준비 → Storage Profile 등록 → 팀에 배정 → 팀원이 공유 → 다른 팀원이 가져오기

요금 비교표에서 "Share Knowledge Stacks, Prompts, Personas"는 Teams 열에만 표시되어 있습니다. [Enterprise 요금제 개요](/guide/enterprise-overview/)를 먼저 보세요.

## 공유할 수 있는 것

| 자원 | 설명 |
|---|---|
| Knowledge Stacks | 문서를 근거로 답하게 하는 자료 묶음 |
| Prompt Library | 저장해 둔 프롬프트 |
| Personas | 역할과 말투를 정해 둔 페르소나 |

문서는 앞으로 더 많은 기능을 저장소와 팀 공유에 지원할 계획이라고 적었습니다. 시기는 나와 있지 않습니다.

업무 예를 들면, 인사팀 담당자가 취업규칙을 Knowledge Stack으로 만들어 공유하면 팀원 모두가 같은 자료를 근거로 질문할 수 있습니다. 규칙이 개정되면 담당자가 고쳐서 다시 공유하고, 팀원은 새로 고침으로 받아 옵니다.

## 쓸 수 있는 저장소

Storage Profile은 S3 호환 저장소의 설정 묶음입니다. 문서가 이름을 든 제공업체는 다음과 같습니다.

- AWS S3
- Cloudflare R2
- Backblaze B2
- DigitalOcean Spaces
- Vultr Object Storage
- 그 밖에 S3 API를 지원하는 모든 제공업체

S3 API를 지원하면 된다고 했으므로, 사내에 설치한 S3 호환 저장소도 원리상 대상이 됩니다. 다만 문서가 사내 설치형 제품의 이름을 들거나 시험 결과를 밝히지는 않았으므로, 실제로 되는지는 **Check Connection**으로 확인해야 합니다.

저장소 사용 요금은 Msty 요금과 별개로 저장소 제공업체에 냅니다.

## Storage Profile 등록하기

### 1. 제공업체 고르기

널리 쓰이는 저장소 제공업체 가운데 하나를 고르거나, 직접 설정하는 S3 호환 항목을 고릅니다. 제공업체에 따라 입력 양식이 다릅니다. 필요한 값은 그 제공업체의 문서와 계정 화면에서 찾습니다.

### 2. 계정 정보 넣기

대부분의 제공업체에서 필요한 값은 다섯 가지입니다.

| 값 | 뜻 |
|---|---|
| Endpoint URL | 저장소에 접속하는 주소 |
| Region ID | 저장소가 있는 지역 |
| Bucket name | 자료를 담을 버킷 이름 |
| Access Key ID | 접근 키의 식별자 |
| Secret Access Key | 접근 키의 비밀값 |

### 3. 연결 시험하기

**Check Connection**을 눌러 값이 맞는지 확인합니다.

### 4. 이름 붙여 저장하기

프로필 이름을 넣고 저장합니다. 팀을 만들 때 이 이름으로 고르게 되므로 "법무팀 공유 저장소"처럼 알아보기 쉽게 붙입니다.

## 저장소를 준비할 때 권하는 점

문서에는 없지만 저장소 운영에서 흔히 지키는 것들입니다.

- **전용 버킷을 만듭니다.** 다른 용도의 버킷과 섞지 않습니다.
- **전용 접근 키를 만듭니다.** 그 버킷에만 닿는 권한을 줍니다. 계정 전체 권한의 키를 넣지 않습니다.
- **버킷을 공개로 두지 않습니다.**
- **지역을 정합니다.** 자료를 국내에 두어야 한다면 그에 맞는 지역이나 제공업체를 고릅니다. 지역 선택은 전적으로 회사의 몫입니다.
- **팀마다 저장소를 나눌지 정합니다.** 팀별로 다른 Storage Profile을 배정하면 팀 사이에 자료가 섞이지 않습니다.

## Studio Web을 위한 CORS 설정

문서가 따로 짚은 문제입니다. 저장소가 올바로 설정되어 있지 않으면 CORS 문제 때문에 Msty Studio Web에서 공유가 되지 않을 수 있습니다.

해결 방법은 S3 버킷의 권한 설정을 고쳐 `msty.studio`에서 오는 요청을 허용하는 것입니다.

CORS는 브라우저가 다른 사이트로 요청을 보낼 때 그 사이트가 허락했는지 확인하는 장치입니다. Studio Web은 브라우저에서 돌아가므로, 저장소가 `msty.studio`를 허락해야 합니다. 데스크톱에서는 공유가 되는데 웹에서만 안 된다면 이 설정을 먼저 보세요.

## 팀에 배정하기

Storage Profile을 등록한 뒤, 팀을 만들거나 고칠 때 **Storage** 항목에서 고릅니다. 팀에 저장소가 배정되어 있지 않으면 그 팀원은 공유할 수 없습니다. [팀 관리](/guide/enterprise-teams/)를 보세요.

## 공유하기

Knowledge Stacks, Prompts, Personas 모두 같은 방식입니다. 자원 하나를 공유할 수도 있고 폴더째 공유할 수도 있습니다.

1. 왼쪽 목록에서 공유할 자원 또는 그것이 든 폴더를 찾습니다.
2. 말줄임표(…) 메뉴를 엽니다.
3. **Share to Cloud**를 고릅니다.

자원 또는 폴더가 팀에 배정된 클라우드 저장소로 올라갑니다.

## 공유된 것 가져오기

받는 사람은 자기 계정에서 말줄임표 메뉴를 열어 공유된 항목을 가져옵니다.

## 공유한 것 관리하기

Admin, Owner, 그리고 공유한 본인은 **Manage**를 골라 공유된 항목을 보고 클라우드 저장소에서 없앨 수 있습니다.

원본을 고친 뒤에는 다시 공유할 수 있습니다. 고친 내용은 자동으로 올라가지 않으므로, 고칠 때마다 다시 공유해야 다른 사람이 받을 수 있습니다.

## 새로 고침

사용자는 공유된 항목을 새로 고쳐 최신 내용을 받아 옵니다. 폴더를 새로 고치면 그 안의 모든 항목이 새로 고쳐집니다.

문서가 밝힌 동작 두 가지를 꼭 알아 두세요.

| 동작 | 내용 |
|---|---|
| 클라우드에서 없앤 항목 | 사용자의 로컬 목록에서는 없어지지 않습니다 |
| 로컬에서 고친 공유 항목 | 새로 고치면 클라우드 판으로 덮어써집니다 |

둘째가 중요합니다. 공유받은 프롬프트를 내 입맛대로 고쳐 쓰다가 새로 고침을 누르면 고친 내용이 사라집니다. 문서의 해결책은 새로 고치기 전에 그 항목을 다른 폴더로 옮겨 두는 것입니다.

첫째도 기억할 점입니다. 관리자가 잘못 공유한 자료를 클라우드에서 없애도, 이미 가져간 사람의 기기에는 남아 있습니다. 회수가 필요하면 각자 지우도록 따로 알려야 합니다.

## 운영 규칙 예시

문서에는 운영 규칙이 없습니다. 팀에서 정해 두면 혼란이 줄어드는 것들입니다.

1. **공유 폴더의 주인을 정합니다.** 누가 고치고 다시 공유하는지 한 사람으로 정합니다.
2. **받은 것을 고치려면 복사본으로 합니다.** 다른 폴더로 옮긴 뒤 고칩니다.
3. **개정하면 알립니다.** 새로 고침은 각자 눌러야 하므로 메신저로 알려 줍니다.
4. **이름에 날짜나 판을 넣습니다.** 예: "취업규칙 2026-10".
5. **민감한 문서는 공유 전에 확인합니다.** 한번 가져간 것은 원격으로 회수되지 않습니다.

## 조직 전체의 지식 관리와의 관계

여기서 설명한 공유는 Studio 사용자끼리 자원을 주고받는 기능입니다. 버전 기록이나 승인 절차는 문서에 나와 있지 않습니다. 조직 전체가 승인된 자료를 버전별로 관리하는 용도로 Msty가 예고한 제품은 Stack이며 아직 출시되지 않았습니다. [Msty Stack 자세히 보기](/guide/product-stack/)를 보세요.
