## Shortcuts란

같은 지시를 매번 길게 입력하고 있다면 **Shortcuts**로 줄일 수 있습니다. 자주 쓰는 지시를 슬래시 명령으로 저장해 두는 기능입니다.

문서는 이를 지나치게 자동화하지 않으면서 사람들의 작업 방식을 맞추는 가장 빠른 방법 가운데 하나로 소개합니다. [Playbook](/guide/go-playbooks/)이 여러 단계의 절차를 담는다면, Shortcut은 한 번의 지시를 담는 가벼운 도구입니다.

예를 들어(필자가 든 예입니다) `/회의록`이라는 Shortcut에 "아래 내용을 결정 사항, 할 일, 담당자, 기한으로 나눠 정리해 줘"라는 틀을 넣어 두고, 실행할 때 회의 메모만 붙여 넣습니다.

## 두 가지 범위

| 범위 | 쓸 수 있는 곳 | 쓰는 경우 |
|---|---|---|
| Global | 넓게 어디서나 | 누구에게나 통하는 일반 작업 |
| Agent-scoped | 특정 에이전트 맥락 안에서만 | 전문 작업 흐름 |

팀으로 일할 때는 이 구분이 특정 업무용 지시가 관련 없는 작업으로 새어 나가는 것을 막아 줍니다.

## 입력 항목

| 항목 | 설명 |
|---|---|
| Slash name | `/name` 형식의 명령 이름 |
| Description | 무엇을 하는지 설명 |
| Prompt template | 실제로 보내질 지시의 틀 |
| Input hint | 사용자가 무엇을 입력해야 하는지 알려 주는 안내(선택) |
| Icon | 아이콘 |

문서는 설명과 입력 안내를 "약속의 일부"로 다루라고 합니다. 이 두 가지가 잘 적혀 있으면 잘못 쓰는 일이 줄고, 여러 사람이 쓰기에 안전해집니다.

Prompt template 안에서 사용자 입력이 들어갈 자리를 표시하는 문법은 공식 문서에 설명이 없습니다.

## 만드는 순서

**Shortcuts** 또는 **Settings > Shortcuts**에서 만듭니다.

1. 빈 상태에서 만들거나, 기본 제공 예시를 복제합니다.
2. 쓸모 있는 가장 작은 틀을 씁니다.
3. 사용자가 맥락을 넣어야 한다면 입력 안내를 더합니다.
4. 실제와 비슷한 프롬프트로 시험합니다.
5. 더 분명하고 일관되게 다듬습니다.

좋은 Shortcut은 구체적인 결과 하나에서 시작합니다. 하나의 Shortcut으로 서로 관련 없는 여러 의도를 처리하려 하지 않습니다.

## 실행할 때의 동작

| 조건 | 동작 |
|---|---|
| 입력이 필요한 Shortcut | Go가 입력을 요청합니다 |
| 입력이 필요 없는 Shortcut | 바로 실행을 시작합니다 |

이 동작은 안전장치로도 쓸 수 있습니다. 입력을 필수로 해 두면, 실행이 시작되기 전에 사용자가 빠진 맥락을 채우게 됩니다.

## 설계 요령

- 슬래시 이름은 짧고, 분명하고, 겹치지 않게 짓습니다.
- 설명은 무엇이 나오는지를 중심으로 씁니다.
- 지나치게 넓은 틀을 피합니다.
- 결과에 특정 업무 맥락이 필요하면 에이전트 범위 Shortcut으로 따로 만듭니다.

Shortcut에 예외 조건이 쌓이기 시작하면, 분기하는 문구를 더 넣지 말고 더 분명한 Shortcut 두 개로 나눕니다.

## 먼저 만들어 볼 만한 분야

문서가 가치가 높다고 든 분야는 네 가지입니다.

| 분야 | 예(필자가 든 것) |
|---|---|
| 검토와 분류 | 들어온 요청을 긴급도별로 나누기 |
| 상태·보고서 형식 맞추기 | 메모를 주간 보고 양식으로 바꾸기 |
| 결정 요약 | 긴 논의에서 결정 사항만 뽑기 |
| 반복되는 코드·내용 변환 | 표를 정해진 형식으로 바꾸기 |

자주 쓰면서 위험이 낮은 분야부터 시작합니다. 문구와 결과 품질이 안정된 뒤에 영향이 큰 동작으로 넓힙니다.

## 관련 기능과의 구분

| 하려는 일 | 맞는 기능 |
|---|---|
| 자주 쓰는 지시 한 번을 빠르게 | Shortcuts |
| 여러 단계의 절차를 반복 | [Playbooks](/guide/go-playbooks/) |
| 정해진 시각에 자동 실행 | [Tasks](/guide/go-tasks/) |
| 특정 상황에서 자동으로 안내하거나 막기 | [Rules](/guide/go-rules/) |

Go에는 Shortcut 외에도 슬래시로 시작하는 명령이 있습니다. 확장 기능 문서의 `/create-extension`처럼 내장 스킬이 제공하는 명령이 그 예이고, [Extensions](/guide/go-extensions/)가 슬래시 명령을 추가할 수도 있습니다. [Context Scout](/guide/go-context-scout/)는 슬래시 명령으로 시작하는 프롬프트에는 동작하지 않습니다.

## 알아 둘 점

- 한글 슬래시 이름을 쓸 수 있는지는 공식 문서에 설명이 없습니다. 위의 `/회의록`은 설명을 위한 예이며, 실제로는 영문 이름이 안전할 수 있습니다.
- Shortcut을 내보내거나 팀과 공유하는 방법은 이 문서 페이지에 설명이 없습니다.
- 기본 제공 예시에 무엇이 들어 있는지도 문서에 나열되어 있지 않습니다.
