## 채널이란

**Channels**는 Go가 원격 플랫폼을 통해 메시지를 받고 보내게 해 줍니다. 자리를 비운 동안 메신저로 에이전트에 지시하거나, 예약 작업의 결과를 메신저로 받는 데 씁니다.

문서는 로컬 에이전트 실행이 안정된 뒤에 도입하라고 거듭 권합니다. 설정 위치는 **Settings > Remote Routes**입니다.

## 지원 플랫폼

| 플랫폼 | 비고 |
|---|---|
| Discord | |
| Telegram | |
| WhatsApp | QR로 연결. 설정이 더 까다롭습니다 |
| Msty Go (모바일 경로) | 계정에 기능이 켜져 있을 때 |
| Android 앱 | 초대제. 계정별로 접근이 열립니다 |

문서는 플랫폼 선택을 운영상의 결정으로 보라고 합니다. 팀이 이미 꾸준히 지켜보는 채널을 먼저 고르고, 보조 경로는 그다음에 더합니다.

iOS 앱에 대한 조건은 이 문서 페이지에 적혀 있지 않습니다. 모바일 앱 전반에 대한 내용은 [Msty Go 자세히 보기](/guide/product-go/)를 참고합니다.

## 연결 순서

1. 채널 계정 또는 세션을 연결합니다.
2. 채널 프리셋을 만듭니다.
3. 에이전트나 Task를 그 프리셋에 묶습니다.
4. 통제된 시험 메시지로 검증합니다.

검증을 건너뛰지 않습니다. 시험 메시지 하나로 경로나 발신자 정책의 실수를 실제 대화에 영향을 주기 전에 잡아낼 수 있습니다.

Discord와 Telegram에서 계정을 연결하는 구체적인 단계(봇 토큰 발급 등)는 공식 문서에 설명이 없습니다. 앱의 설정 화면 안내를 따라야 합니다.

## 채널 프리셋

프리셋은 경로를 일관되고 안전하게 유지합니다. 프리셋 하나에 저장되는 것은 다음과 같습니다.

| 항목 | 설명 |
|---|---|
| Platform | 어느 플랫폼인가 |
| Channel connection | 어느 연결을 쓰는가 |
| Destination address/chat ID | 보낼 주소 또는 대화방 ID |
| Trigger word | 호출어(선택) |
| Sender-group policy | 누가 쓸 수 있는가 |

프리셋을 쓰면 변경 관리도 쉬워집니다. 프리셋 하나를 고치면 거기에 묶인 모든 자동화가 같은 경로 정책을 물려받습니다. 문제가 생겼을 때도 목적지와 접근 정책이 한곳에서 보이므로 원인을 찾는 시간이 크게 줄어든다고 문서는 설명합니다.

호출어가 정확히 어떻게 동작하는지(예: 메시지가 호출어로 시작해야 하는지)는 공식 문서에 설명이 없습니다.

## 접근 제한

프리셋의 접근 옵션은 두 가지입니다.

| 옵션 | 뜻 |
|---|---|
| `Anyone in this chat` | 그 대화방의 누구나 |
| `Restrict access` | Sender Groups로 제한 |

여러 사람이 있는 대화방에 에이전트를 붙인다면 이 선택이 중요합니다. `Anyone in this chat`으로 두면 대화방의 모든 사람이 내 컴퓨터의 에이전트를 움직일 수 있습니다.

문서의 보안 기준은 공유 채널을 켜기 전에 Sender Groups를 먼저 제한하는 것입니다. Sender Groups는 [보안 설정](/guide/go-security/)에서 만듭니다.

## WhatsApp 유의점

WhatsApp 설정은 QR로 연결하고, 들어오는 메시지가 보이기 시작한 뒤에 대화 대상을 고르는 순서로 진행됩니다.

문서는 Discord나 Telegram보다 상태에 더 많이 의존한다고 설명합니다. 재연결이나 기기 교체 상황에 대비해 담당자가 관리하는 점검표를 두라고 권합니다.

## Msty Go 모바일 경로

계정에 기능이 켜져 있으면 Msty Go를 통한 모바일 경로를 쓸 수 있습니다.

1. **Settings > Cloud > Msty Go**에서 QR 설정으로 휴대전화를 연결합니다.
2. 모바일로 보내기 전에 데스크톱에서 전화 접근을 켭니다.
3. 채널 프리셋으로 모바일 경로를 지정합니다. 대상은 `all-devices` 또는 범위가 정해진 경로 ID입니다.
4. 앱이나 데스크톱을 업데이트한 뒤에는 재연결 동작을 검증합니다.

문서의 권고는 운영자의 응답 속도가 중요한 우선순위 높은 작업에 모바일 경로를 쓰는 것입니다. 우선순위가 낮은 자동화는 데스크톱 경로에 두어 알림 소음을 줄입니다.

앱이나 계정에 변화가 있은 뒤에는 검증을 계속하라는 당부도 있습니다. 경로가 조용히 어긋나는 일을 막기 위해서입니다.

휴대전화 연결의 사전 조건(데스크톱 동기화 설정 등)은 [Cloud Sync](/guide/go-cloud-sync/)에 있습니다.

## Local only로도 충분하다

채널은 선택 사항입니다. 에이전트는 원격 통합 없이 **Local only**로 실행할 수 있습니다. 문서는 관리 방식과 경로 요구가 분명해질 때까지 많은 팀에 이것이 맞는 기본값이라고 적습니다.

Setup 문서가 제시하는 채널 도입 조건은 세 가지입니다.

- 로컬 에이전트 실행이 안정적이다.
- 보안 기준이 이미 설정되어 있다.
- 원격 경로가 실제로 필요하다.

## 채널을 쓰는 곳

| 쓰는 곳 | 방법 |
|---|---|
| [에이전트](/guide/go-agents/) | 경로를 `Channel preset`으로 정합니다 |
| [Tasks](/guide/go-tasks/) | 결과를 보낼 곳으로 채널 프리셋을 고릅니다 |

## 운영 요령

- 운영 경로에는 한 번 쓰고 마는 값이 아니라 프리셋을 씁니다.
- 공유 채널에서는 발신자 제한을 명시합니다.
- 플랫폼이나 에이전트 권한이 바뀐 뒤에는 프리셋을 다시 검증합니다.
- 영향이 큰 자동화에 앞서 위험이 낮은 작업부터 시작합니다.

## 보안상 생각할 점

채널을 연결하면 지시와 결과가 해당 메신저 서비스를 거칩니다. 에이전트가 다루는 파일 내용이 결과 메시지에 담겨 외부 서비스로 나갈 수 있다는 뜻입니다. 민감한 자료를 다루는 에이전트라면 채널을 붙이지 않고 `Local only`로 두는 편이 맞습니다. 이 문단은 채널의 동작 방식에서 필자가 끌어낸 주의 사항이며, 문서에 직접 적힌 문장은 아닙니다.

## 문서 사이의 차이

Setup 문서는 채널로 Discord, Telegram, WhatsApp 세 가지만 들고, Channels 문서는 여기에 Msty Go 모바일 경로와 초대제 Android 앱을 더합니다. 휴대전화 연결 위치도 Setup 문서는 **Settings > Cloud**, Channels 문서는 **Settings > Cloud > Msty Go**로 적습니다. 뒤쪽이 더 구체적인 경로입니다.
