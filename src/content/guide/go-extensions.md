## Extensions란

**Extensions**(확장 기능)는 Go에 테마, 도구, 자동화, 모델 옵션, 사용자 정의 화면, 앱 화면 요소를 더하는 묶음입니다. 한 번 쓰고 마는 프롬프트나 손으로 하는 설정이 아니라, 다시 쓰고, 설치하고, 권한을 검토할 수 있는 형태로 작업 흐름을 만들고 싶을 때 씁니다.

앱 내비게이션의 **Extensions**에서 열거나 `Cmd/Ctrl + Shift + X`를 누릅니다.

## 세 개의 구역

| 구역 | 하는 일 |
|---|---|
| **Discover** | 카탈로그의 확장 기능을 살펴보고, 세부 정보를 확인하고, 업데이트를 설치하고, 평점을 줍니다 |
| **Installed** | 설치한 확장 기능의 권한, 설정, 로그, 활동, 저장소, 업데이트, 제거를 관리합니다 |
| **Authoring** | 새 확장 기능을 만들고, Verified Extension Authoring을 신청하고, 승인되면 완성된 패키지에 서명합니다 |

어느 구역에 있든 **Install from ZIP**으로 로컬 패키지를 설치할 수 있습니다.

## 확장 기능이 할 수 있는 일

사용자가 승인한 권한에 따라 눈에 보이는 화면 요소와 배경 기능을 더할 수 있습니다.

| 종류 | 더하는 것 |
|---|---|
| 테마 | 앱 테마와 테마 설정 |
| 명령과 도구 | 슬래시 명령, 호출 가능한 도구, 작업 흐름 동작 |
| Rules, Playbooks, Tasks | 재사용할 수 있는 자동화 구성 요소 |
| 트리거 제공자 | 자동 Task 실행을 일으키는 새 이벤트 원천 |
| 화면 요소 | 전체 화면, 서랍, 대화 상자, 팝업, 제목 표시줄 항목, 상태 표시줄 표시, 작업 공간 항목, 도구함 항목, Pulse 항목, 메시지 동작, 입력창 동작 |
| 모델 기능 | 모델 배정 칸, 가상 모델, 로컬 모델 통합 |

### Skills Hub와 무엇이 다른가

문서의 구분은 이렇습니다. 스킬은 주로 모델의 행동과 지시를 묶은 것입니다. 확장 기능은 Go 앱 자체에 더 깊이 결합할 수 있지만, 필요한 접근 권한을 반드시 선언해야 합니다.

## Discover에서 찾기

**Extensions > Discover**에서 쓸 수 있는 기능입니다.

- 이름, 설명, 작성자, 키워드, 메타데이터로 검색
- 분류별로 걸러 보기
- 설치됨·설치 안 됨으로 걸러 보기
- `Popular`, `New`, `Top rated`, `Name` 순으로 정렬
- 세부 정보 서랍: 설치 버튼, 권한 미리보기, 추가되는 항목 요약, 평점, 소스 링크, 메타데이터

정렬 항목은 페이지마다 다르게 적혀 있습니다. Go 문서는 위 네 가지를 들고, 제품 페이지의 확장 목록에는 Featured, Most downloaded, Top rated, Name이 표시됩니다. 앱 안의 실제 표기는 직접 확인하는 것이 정확합니다.

설치하기 전에 세부 정보 서랍에서 다음을 검토합니다.

1. 확장 기능이 무엇을 더하는가
2. 어떤 권한을 요청하는가
3. 신뢰 표시와 작성자 정보
4. 소스나 지원 링크(있는 경우)
5. 버전, 게시일, 갱신일, 라이선스, 내려받은 횟수, 평점

## 공개 저장소

확장 기능에는 공개 GitHub 저장소가 있습니다. 주소는 [cloudstack-llc/msty-claw-extensions](https://github.com/cloudstack-llc/msty-claw-extensions)입니다. 저장소 이름에 Go의 예전 이름인 Claw가 남아 있습니다.

- 확장 기능의 구조와 만드는 법 익히기
- 제작 안내서, 매니페스트 스키마, 런타임 API 타입 확인하기
- Discover에 올라 있는 확장 기능 둘러보기
- 각 확장 기능의 README, 매니페스트, 소스 파일 읽기
- 설치하거나 권한을 승인하기 전에 무슨 일을 하는지 확인하기
- Msty 검토와 Discover 등재를 준비하기

등재된 확장 기능은 저장소의 `extensions/` 아래에 각자 패키지 파일을 두고 있습니다.

## 설치와 권한 검토

1. Discover에서 **Install**을 누르거나 **Install from ZIP**을 고릅니다.
2. 세부 정보와 요청된 접근 권한을 검토합니다.
3. 패키지를 설치합니다.
4. Go가 접근 권한을 보류 상태로 표시하면 권한 검토 화면을 엽니다.
5. 쓰려는 작업에 필요한 권한만 허용합니다.

필수 권한은 검토를 거쳐야 확장 기능이 온전히 실행됩니다. 필수 권한을 거부하거나 취소하면, 접근 설정을 바꾸기 전까지 확장 기능이 제한되거나 쓸 수 없는 상태로 남을 수 있습니다.

## 설치한 확장 기능 관리

**Extensions > Installed**에서 할 수 있는 일입니다.

- 설치한 확장 기능 검색, 걸러 보기, 정렬
- 보류 중인 권한 검토
- 권한을 하나씩 허용, 거부, 취소
- 확장 기능 켜기·끄기
- 확장 기능 설정 열기
- 활동, 로그, 작업, 저장소 살펴보기
- 확장 테마 적용
- 카탈로그가 관리하는 확장 기능 업데이트
- 하나 또는 전부 제거

확장 기능이 동작하지 않으면 권한, 설정, 로그와 활동 순으로 확인합니다.

## 직접 만들기

확장 기능은 ZIP 패키지입니다. 루트에 `manifest.json`이 있고, 선택적으로 JavaScript 진입 파일과 아이콘·미리보기 같은 정적 자료가 들어갑니다. 문서가 보여 주는 단순한 구성은 다음과 같습니다.

```
my-extension/
  manifest.json
  extension.js
  static/
    icon.svg
```

- 확장 ID는 `com.yourname.extension-name`이나 `ai.yourteam.extension-name` 같은 역방향 DNS 형식으로, 바뀌지 않게 정합니다.
- 권한은 최소한으로 요청하고, 권한마다 왜 필요한지 분명한 이유를 적습니다.
- `manifest.json`이 ZIP의 루트에 오도록 확장 기능 폴더 안에서 압축합니다.

```
cd my-extension
zip -r my-extension.zip manifest.json extension.js static
```

그런 다음 **Extensions > Install from ZIP**으로 설치하고 권한을 검토합니다.

### Go에게 만들게 하기

가장 빠른 길은 **Extensions > Authoring > Create a new extension**입니다. **Start building**을 누르면 확장 제작용 프롬프트가 들어간 대화가 열립니다. 프롬프트를 복사해 새 대화에 붙여도 됩니다.

Go는 내장 `create-extension` 스킬로 꼭 필요한 것만 묻고, 패키지 뼈대를 만들고, 매니페스트를 검증하고, 시험용 ZIP을 만들고, 내린 결정을 쉬운 말로 설명합니다. 대화에서 바로 시작할 수도 있습니다.

```
/create-extension Build a small extension that...
```

요청에 넣으면 좋은 내용은 다음과 같습니다.

- 확장 기능 이름과 작성자
- 원하는 확장 ID, 또는 Go가 제안해도 된다는 허락
- 앱의 어디에 나타나야 하는가
- 어떤 사용자 동작이 실행을 일으키는가
- 어떤 데이터를 읽거나 써야 하는가
- 설정, 저장소, 파일, 네트워크 접근, 모델 호출이 필요한가

ZIP이 만들어지면 다른 사람과 나누기 전에 먼저 혼자 설치해 동작을 검증합니다.

## 비공개로 쓰기

공개 카탈로그에 올리지 않아도 확장 기능을 쓸 수 있습니다.

- 내 ZIP을 **Install from ZIP**으로 설치
- 믿을 수 있는 동료에게 ZIP을 직접 전달
- 소스를 비공개 저장소에 보관
- 계정에 Verified Extension Authoring이 있으면 서명된 ZIP을 비공개로 사용

비공개 확장 기능도 로컬 패키지 검증과 권한 검토를 거칩니다. 받는 사람은 켜기 전에 소스, 요청 권한, 신뢰 표시를 살펴봐야 합니다.

## Verified Author로 공유하기

패키지에 **Verified Author** 표시를 붙이고 싶은 작성자를 위한 절차입니다. **Extensions > Authoring > Share as a verified author**에서 진행합니다.

| 상태 | 뜻 |
|---|---|
| **Signed out** | 신청 전에 Msty Go Cloud에 로그인해야 합니다 |
| **Apply** | 로그인한 계정 이메일과 Discord 사용자 이름(선택)으로 신청합니다 |
| **Pending** | Msty가 신청을 받았습니다 |
| **Needs info** / **Rejected** | 신청 내용을 고쳐 다시 제출합니다 |
| **Ready** | 계정으로 확장 ZIP에 서명할 수 있습니다 |

준비되면 **Sign an extension ZIP**을 고릅니다. Go가 패키지를 검사하고, 인증된 계정 이름이 들어간 서명본을 저장합니다.

문서가 분명히 해 둔 한계가 있습니다. Verified Author는 승인된 Msty 계정이 패키지에 서명했다는 사실을 확인해 줄 뿐입니다. Msty가 코드를 전부 감사했다는 뜻이 아닙니다.

## 공개 카탈로그에 올리기

Discover에 공개되는 것은 검토를 거치는 별도의 길입니다. Go 안에 자동으로 공개하는 스위치는 없습니다. 제출 전에 준비할 것은 다음과 같습니다.

- ZIP으로 로컬에서 시험하기
- 요청 권한을 최소한으로, 이유와 함께
- 필요하면 소스나 저장소 정보 준비
- 분명한 이름, 설명, 버전, 아이콘, 분류, 지원 URL, 라이선스
- 인증된 작성자로 표시되기를 원하면 Verified Extension Authoring 사용

패키지와 메타데이터는 "현재의 Msty 검토 창구"로 제출한다고만 적혀 있고, 구체적인 제출 주소는 공식 문서에 설명이 없습니다. 문서는 Authoring 탭에서 [Msty Discord](https://msty.ai/discord)에 참여하면 검토가 빨라진다고 안내합니다.

## 평점 주기

평점은 Msty Go Cloud 계정에 연결됩니다.

1. Msty Go Cloud에 로그인합니다.
2. **Extensions > Discover**를 엽니다.
3. 확장 기능의 세부 정보 서랍을 엽니다.
4. 별 1~5개 가운데 고릅니다.

로그아웃 상태면 **Sign in to rate**가 표시될 수 있습니다. 로컬 ZIP 설치에는 로그인이나 평점이 필요 없습니다.

## 신뢰 표시

| 표시 | 뜻 |
|---|---|
| **Official** | Msty 팀이 서명 |
| **Verified Author** | 인증된 Msty 작성자가 서명 |
| **Reviewed** | 확장 카탈로그를 통해 검토됨 |
| **Signed** | 패키지 무결성은 서명되었지만 작성자는 Msty가 인증하지 않음 |
| **Unverified Author** | 작성자 신원이 인증되지 않음 |

문서는 신뢰 표시를 유일한 판단 근거가 아니라 여러 근거 가운데 하나로 쓰라고 합니다. 권장 기준은 다음과 같습니다.

- 이해하고 신뢰하는 확장 기능만 설치합니다.
- 접근을 허용하기 전에 권한을 검토합니다.
- 넓은 접근보다 좁은 권한을 택합니다.
- 개인 인증 정보를 확장 코드나 일반 저장소에 두지 않습니다.
- 쓰지 않는 확장 기능은 끄거나 제거합니다.
- 업데이트 뒤에는 권한을 다시 확인합니다.

## 문제 해결

| 증상 | 조치 |
|---|---|
| 설치했는데 아무 일도 없다 | Installed에서 보류 중인 권한을 검토하고 확장 기능을 켭니다 |
| 설정을 열 수 없다 | 필수 권한을 검토하거나 확장 기능을 켭니다 |
| 업데이트 뒤 멈췄다 | 업데이트가 새로 요청한 접근 권한을 검토합니다 |
| 평점을 줄 수 없다 | Msty Go Cloud에 로그인합니다 |
| 제작자 신청을 할 수 없다 | Msty Go Cloud에 로그인하고 Authoring 탭의 상태를 확인합니다 |
| 비공개 ZIP이 설치되지 않는다 | `manifest.json`이 ZIP 루트에 있는지, 지원되는 확장 API 버전을 쓰는지 확인합니다 |
