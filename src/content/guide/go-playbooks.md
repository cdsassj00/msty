## Playbooks란

**Playbooks**는 한 번 성공한 실행을 반복할 수 있는 작업 흐름으로 바꿔 둔 것입니다. 사람이 바뀌어도, 에이전트가 바뀌어도, 시간이 지나도 같은 방식으로 일이 처리되기를 바랄 때 씁니다.

예를 들어(필자가 든 예입니다) 매달 민원 접수 목록을 읽어 유형별로 나누고 요약 보고서를 만드는 일을 한 번 잘 해냈다면, 그 과정을 Playbook으로 만들어 다음 달부터는 설명을 반복하지 않고 실행합니다.

## 좋은 Playbook에 들어가는 것

| 요소 | 내용 |
|---|---|
| 의도와 시작 조건 | 무엇을 위한 것이고 언제 돌리는가 |
| 필요한 입력 | 실행에 꼭 있어야 하는 자료 |
| 순서가 있는 실행 단계 | 무엇을 어떤 순서로 하는가 |
| 안전장치와 승인 기대 | 어디서 멈추고 사람에게 묻는가 |
| 성공 기준 | 무엇이 되면 끝난 것인가 |
| 모델·작업 공간 맥락 | 선택 사항 |

이 요소들이 명시적일수록, 서로 다른 사람이 실행해도 비슷한 결과를 얻기 쉽습니다.

## 만드는 세 가지 방법

| 방법 | 설명 |
|---|---|
| 내장 카탈로그에서 시작 | 기본 제공되는 출발용 Playbook을 바탕으로 합니다 |
| 직접 작성 | 처음부터 씁니다 |
| Teach-mode 세션 | 대화를 Playbook으로 바꿉니다(chat-to-playbook) |

문서의 지침은 두 가지입니다.

- 검증된 실제 실행에서 시작합니다.
- 우연히 끼어든 세부 사항이 아니라 반복되는 논리를 뽑아냅니다.

가상의 작업 흐름으로 Playbook을 만드는 것은 피하라고 합니다. 실제 실행 기록에서 나온 단계가 대개 더 분명하고 믿을 만합니다.

Teach-mode를 시작하는 정확한 메뉴 위치와 내장 카탈로그에 무엇이 들어 있는지는 공식 문서에 설명이 없습니다.

## 실행 방식

Playbook은 상황에 따라 현재 대화나 새 대화에서 실행할 수 있고, 예약할 수도 있습니다.

| 방식 | 맞는 경우 |
|---|---|
| 대화에서 직접 실행 | 익히고 다듬는 단계 |
| 예약 실행 | 안정된 반복 작업 |

얼마나 지켜봐야 하는지에 따라 고릅니다. 예약은 [Tasks](/guide/go-tasks/)에서 설정합니다.

### 어떤 에이전트가 실행할지 고르기

Playbook을 어느 에이전트가 실행할지 선택할 수 있습니다. 마침 열려 있는 대화에 맡기는 대신, 알맞은 권한·실행 방식·작업 방식을 가진 에이전트에 맞춰 실행하기 위해서입니다. 에이전트 구성은 [에이전트 만들기와 관리](/guide/go-agents/)를 참고합니다.

### 권장 도입 순서

1. 작은 범위로 수동 실행합니다.
2. 결과 품질과 승인 동작을 검증합니다.
3. 믿을 만하다는 것이 확인된 뒤 범위를 넓히거나 예약합니다.

## Data Protection 적용

Playbook 실행은 프롬프트 내용과 도구 호출 경로 모두에 Data Protection을 적용할 수 있습니다.

Playbook이 민감한 운영 자료나 개인 정보를 다룰 때 씁니다. 문서는 가림 처리가 제대로 되는지를 Playbook 인수 시험의 일부로 검증하라고 권합니다. Data Protection 자체의 설정 방법은 Go 공식 문서에 별도 페이지가 없습니다.

## Auto Refine

**Auto Refine**은 실제 실행에서 개선 후보를 모아 두고, 사용자가 의도적으로 변경을 적용하게 해 줍니다.

문서는 개선 제안을 자동으로 옳은 것이 아니라 제안으로 다루라고 합니다. 사람이 검토해야 동작이 운영 의도에서 벗어나지 않습니다.

- 개선 제안을 정기적으로 모아서 검토합니다.
- 결과를 더 일정하고 분명하게 만드는 변경만 받아들입니다.

보류 중인 개선 제안은 [Pulse](/guide/go-pulse/)가 살펴보는 항목에도 포함됩니다.

## Playbook과 스킬 사이의 변환

Go는 양방향 변환을 지원합니다.

- Playbook → Skill
- Skill → Playbook

대화형 흐름을 재사용 가능한 묶음 형태의 동작으로 옮기고 싶을 때 씁니다. 손으로 반복하던 패턴이 더 넓은 팀을 위해 표준으로 삼을 만큼 다듬어졌을 때 유용합니다. 스킬 관리는 [도구 설정](/guide/go-tools/)의 Skills Hub 항목에서 다룹니다.

## 흔한 실패 유형

| 유형 | 고치는 방향 |
|---|---|
| 단계가 너무 넓거나 모호하다 | 구체적이고 확인할 수 있는 말로 다시 씁니다 |
| 성공 기준이 없다 | 끝났다고 볼 조건을 적습니다 |
| 승인 경계가 불분명하다 | 어디서 사람의 확인을 받을지 적습니다 |
| 한 데이터나 프로젝트에 지나치게 맞춰져 있다 | 우연한 세부 사항을 빼고 반복되는 논리만 남깁니다 |

왼쪽 열은 문서가 든 실패 유형이고, 오른쪽 열은 문서의 다른 지침을 바탕으로 필자가 정리한 것입니다. 문서의 총평은 이렇습니다. 실패가 반복되면 범위를 좁히고, 단계를 구체적이고 시험할 수 있는 말로 다시 쓴 뒤에 다시 넓힙니다.

## 다른 기능과 연결되는 지점

- [Memory Bank](/guide/go-memory-bank/)의 Memory Pack을 Playbook에 붙일 수 있습니다.
- [Extensions](/guide/go-extensions/)가 Playbook을 재사용 가능한 구성 요소로 제공할 수 있습니다.
- 도구를 바꾼 뒤에는 중요한 Playbook을 다시 시험하라고 도구 문서가 권합니다.

## 알아 둘 점

- Playbook의 파일 형식, 내보내기와 공유 방법은 이 문서 페이지에 설명이 없습니다.
- Playbooks 화면을 여는 정확한 메뉴 위치도 적혀 있지 않습니다.
