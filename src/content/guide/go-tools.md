## 도구는 필요할 때만 켠다

도구는 Go가 기본 대화 이상의 일을 하게 해 줍니다. 문서는 좋은 도구 구성을 "불필요한 위험이나 소음을 만들지 않으면서 기능을 더하는 것"이라고 설명합니다. 도구는 기본으로 켜 두는 설정이 아니라 기능 확장으로 다루고, 켜 둔 도구마다 구체적인 업무상 이유가 있어야 합니다.

설정 위치는 **Settings > Tools**입니다.

## 여덟 가지 도구 영역

| 영역 | 하는 일 |
|---|---|
| Context Saver | 출력 줄이기 등 맥락을 아끼는 기능 |
| Context Scout | 보내기 전에 작업 공간에서 관련 파일 찾기 |
| Skills Hub | 스킬 찾기, 설치, 관리 |
| Computer Use | 컴퓨터 화면의 앱을 보고 조작하기 |
| Built-in local MCP endpoint | Go가 제공하는 로컬 MCP 접속 지점 |
| Web search key | 웹 검색 키 설정 |
| Source attribution | 출처 표시 여부 |
| External MCP servers | 외부 MCP 서버 연결 |

## MCP 서버

MCP 서버는 모델이 외부 프로그램이나 서비스를 도구로 쓸 수 있게 해 주는 연결 방식입니다. Go에서 추가할 수 있는 종류는 두 가지입니다.

| 종류 | 연결 방식 |
|---|---|
| `Local command` | `stdio`. 내 컴퓨터에서 명령을 실행해 연결 |
| `Remote URL` | `http`. 원격 주소로 연결 |

원격 MCP 서버는 헤더를 안전하게 저장하고, 저장된 값을 다시 보거나 바꾸는 기능을 지원합니다.

문서가 권하는 첫 도입 순서는 다음과 같습니다.

1. 위험이 낮은 로컬 MCP 서버 하나를 추가합니다.
2. 도구가 나타나는지, 응답 품질이 괜찮은지 확인합니다.
3. 원격 MCP는 보안 검토를 마친 뒤에만 추가합니다.
4. 에이전트가 쓸 수 있는 범위를 조금씩 넓힙니다.

단계를 나누면 문제가 퍼지는 범위가 작아지고, 결과 품질이 나빠졌을 때 어느 통합 기능 때문인지 추적하기 쉽습니다. 외부 MCP마다 담당자를 정해 인증 정보 교체, 장애, 업데이트를 예측 가능하게 처리하라는 조언도 있습니다.

### 내장 로컬 MCP 엔드포인트

Go는 내장 로컬 엔드포인트와 인증 헤더 정보를 제공합니다. 다른 로컬 프로그램에서 Go에 연결하는 상황을 위한 것입니다. 문서는 지연이 적어야 하고 의존 관계를 단순하게 유지하고 싶은 로컬 작업에 쓰라고 안내합니다.

이 엔드포인트가 어떤 도구를 노출하는지, 주소와 포트가 무엇인지는 공식 문서에 설명이 없습니다. 설정 화면에서 확인해야 합니다.

## 웹 검색

Jina 키를 넣으면 검색 기능이 더 넓게 동작합니다.

| 상태 | 동작 |
|---|---|
| 키 없음 | 제한된 동작 |
| 키 있음 | 지원되는 검색 흐름이 모두 켜짐 |

"제한된 동작"이 구체적으로 무엇인지는 공식 문서에 설명이 없습니다.

웹 검색을 쓴 답에는 출처가 표시될 수 있습니다.

- 답변 안에 붙는 출처 배지
- 링크, 도메인, 제목, 발췌문을 보여 주는 **Sources** 서랍
- Network Guard가 막은 결과 수(해당하는 경우)

출처 표시는 팀 환경에서 특히 쓸모가 있습니다. 생성된 답을 나중에 확인할 수 있고, 답을 얼마나 믿어도 되는지에 대한 의문을 줄여 줍니다.

## Context Scout

보내기 전에 작업 공간을 살펴 관련 파일과 작업 요약을 붙여 주는 기능입니다.

| 설정 | 선택지 |
|---|---|
| 모드 | `Fix`, `Plan`, `Review` |
| 깊이 | `Lean`, `Balanced`, `Deep` |
| 보내기 전 검토 | 선택 사항 |
| 전용 모델 배정 | 선택 사항 |

대화에 작업 공간이 없거나 에이전트 대화 안에서는 쓸 수 없습니다. 모든 프롬프트가 아니라 저장소나 작업 공간 맥락에 따라 답의 품질이 달라질 때 씁니다. 자세한 사용법은 [Context Scout](/guide/go-context-scout/)에 있습니다.

## Skills Hub

**Skills Hub**는 스킬을 찾고, 살펴보고, 설치하고, 업데이트하고, 끄고, 지우는 작업을 앱 안에서 하게 해 줍니다. 스킬을 사람끼리 파일로 주고받는 대신, 관리 상태가 보이는 곳에서 버전과 함께 다루기 위한 것입니다.

- 신뢰하는 출처의 스킬만 설치합니다.
- 넓게 쓰기 전에 위험이 낮은 작업에서 동작을 확인합니다.
- 오래되었거나 겹치는 스킬은 검토해서 끕니다.

스킬과 확장 기능의 차이는 [Extensions](/guide/go-extensions/)에서 설명합니다. 스킬과 Playbook은 서로 변환할 수 있으며, [Playbooks](/guide/go-playbooks/)에서 다룹니다.

## Computer Use

**Computer Use**는 호환되는 대화와 에이전트가 내 컴퓨터의 앱을 보고 조작하게 해 줍니다. macOS와 Windows에서 쓸 수 있습니다.

설정 순서는 다음과 같습니다.

1. **Settings > Tools**에서 로컬 도우미 프로그램을 설치합니다.
2. 설치가 끝나면 Computer Use를 전체 설정에서 켭니다.
3. 화면 조작이 필요한 대화나 에이전트마다 따로 켭니다.
4. macOS에서는 요청이 뜰 때 Accessibility(손쉬운 사용)와 Screen Recording(화면 기록) 권한을 허용합니다.
5. Windows에서는 앱 안의 설정·점검 흐름을 따릅니다.

전체 설정에서 켜고, 다시 대화나 에이전트 단위로 켜는 두 단계 구조라는 점을 기억해 둡니다.

작업에 화면 조작이 정말 필요할 때만 씁니다. 파일, API, 셸 명령, MCP 도구로 끝낼 수 있다면 그쪽이 더 안전하고 예측 가능하다는 것이 문서의 입장입니다. 에이전트 쪽 운영 지침은 [에이전트](/guide/go-agents/)에 있습니다.

## Context Saver와 Caveman Talk

**Context Saver**에는 다음이 포함됩니다.

- Output Trimming(출력 줄이기) 조절
- 설치 여부와 지원 여부 표시
- 새로 고침과 업데이트

**Caveman Talk**는 답을 극도로 짧게 하는 모드입니다. 문서는 작업 맥락을 이미 잘 알고 있어 설명이 필요 없는 사람에게만 쓰라고 권합니다.

Output Trimming이 무엇을 얼마나 줄이는지, Caveman Talk의 구체적인 출력 형식은 공식 문서에 설명이 없습니다.

## Airlock과 웹 통제

에이전트에 웹 접근이 필요하면 [Airlock](/guide/go-airlock/) 정책으로 허용·차단 사이트를 명시합니다. Airlock, Network Guard, 에이전트 권한을 겹쳐 나가는 접근을 통제합니다.

## 운영 요령

- 도구는 최소한으로 시작합니다.
- 영향이 큰 도구는 에이전트별 정책 뒤에 둡니다.
- 새 도구를 켠 뒤에는 결과 품질과 토큰 사용량을 지켜봅니다.
- 도구를 바꾼 뒤에는 중요한 Playbook을 다시 시험합니다.
