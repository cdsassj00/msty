## 무엇을 하는 기능인가

**Workspace Profile Files**(작업 공간 프로필 파일)는 현재 작업 공간의 루트에 있는 정해진 이름의 파일을 대화와 에이전트의 명시적인 맥락으로 쓰게 해 주는 기능입니다.

"이 폴더에서 일할 때는 이런 말투로, 이런 사용자에게 맞춰서"라는 내용을 파일로 적어 두면, 그 폴더에서 여는 대화와 에이전트가 이를 반영합니다.

설정 위치는 **Settings > General > Use workspace profile files**입니다.

## 지원하는 파일

Go가 현재 작업 공간 루트에서 불러오는 파일 이름은 세 가지뿐입니다.

| 파일 | 용도 |
|---|---|
| `SOUL.md` | 그 작업 공간에 맞는 말투, 가치, 문체, 행동 기대 |
| `IDENTITY.md` | 에이전트 이름이나 보여지는 모습처럼 밖으로 드러나는 정체성 |
| `USER.md` | 그 작업 공간과 관련된 사용자나 운영자의 선호 |

`MEMORY.md`와 그 밖의 OpenClaw 방식 파일은 아직 이 기능으로 불러오지 않습니다. 오래 남길 기억에는 [Memory Bank](/guide/go-memory-bank/)를 쓰라고 문서는 안내합니다.

파일은 간결하고 잘 바뀌지 않는 내용으로 채웁니다. 길거나, 오래되었거나, 서로 모순되는 프로필 파일은 결과 품질을 떨어뜨립니다.

## 우선순위

프로필 파일은 명시적인 작업 공간 맥락으로 다뤄지지만, 가장 우선하는 지시는 아닙니다. 문서가 설명하는 우선순위는 다음과 같습니다.

1. 현재 턴에서는 사용자의 가장 최근 지시가 가장 중요합니다.
2. 충돌이 있으면 프로젝트 지시와 에이전트 사용자 정의 지시가 우선합니다.
3. 프로필 파일은 작업 공간 안에서 정체성, 사용자 선호, 작업 방식을 형성합니다.
4. 붙어 있는 메모리와 Working Brief는 추가 맥락을 줄 뿐, 정책을 대신하지 않습니다.

프로필 파일이 실제 프로젝트 요구와 어긋난다면 대화에서 같은 지적을 반복하지 말고 파일을 고칩니다.

## 불러오기 규칙

기능을 켜면 다음과 같이 동작합니다.

- Go가 현재 작업 공간 루트에서 지원하는 파일 이름을 찾습니다.
- 없는 파일은 무시합니다.
- 빈 파일은 무시합니다.
- 지원하는 파일은 작업 공간 대화와 에이전트의 프롬프트에 들어갑니다.
- 파일마다 불러오기 전에 길이 상한이 적용됩니다. 프로필 파일이 맥락 창을 차지해 버리지 않게 하기 위해서입니다.

기능을 끄면 Go는 지원하는 파일이 있다는 것을 감지할 수는 있지만 그 내용을 모델에 넣지 않습니다.

길이 상한이 정확히 얼마인지는 공식 문서에 설명이 없습니다. 파일을 짧게 유지하는 것이 안전합니다.

## 켜는 순서

1. 현재 쓰는 작업 공간 루트에 `SOUL.md`, `IDENTITY.md`, `USER.md`가 있는지, 있다면 내용이 무엇인지 먼저 읽어 봅니다.
2. **Settings > General**을 엽니다.
3. **Use workspace profile files**를 켭니다.
4. 그 작업 공간에서 대화를 열어 반영되는지 확인합니다.

1번을 먼저 하는 이유가 있습니다. Setup 문서는 작업 공간 루트의 파일을 검토한 뒤에만 이 기능을 켜라고 권합니다. 다른 사람이 만든 저장소를 내려받았다면, 그 안의 프로필 파일이 내 에이전트의 행동을 바꿀 수 있기 때문입니다.

## 작성 예

문서는 구체적인 지침을 짧은 절로 나눠 적으라고 권하고, 두 가지 구조 예를 보여 줍니다. 아래는 그 구조를 따라 한국어 업무 상황에 맞게 필자가 다시 쓴 예입니다.

`USER.md` 예:

```
# 사용자 선호

- 결론을 먼저, 다음 할 일을 분명하게 적는다.
- 위험한 가정은 실행 전에 알린다.
- 진행 보고는 짧게 한다.
```

`SOUL.md` 예:

```
# 작업 공간 방식

- 실용적으로, 실행 중심으로 답한다.
- 가장 작은 확인 절차로 결과를 검증한다.
- 일상적인 변경은 길게 설명하지 않는다.
```

## 운영 요령

- 공유 작업 공간에서 기능을 켜기 전에 프로필 파일을 검토합니다.
- 민감한 인증 정보는 프로필 파일에 넣지 않습니다.
- 내용이 저장소에 올려도 되는 경우에만 파일을 버전 관리에 포함합니다.
- 여러 작업 공간에 걸쳐 써야 하는 오래가는 사실은 Memory Bank에 둡니다.
- 프로필 파일을 고친 뒤에는 중요한 에이전트를 다시 시험합니다.

## 에이전트와 Side Chat에서

- [에이전트](/guide/go-agents/) 문서는 작업 공간 루트의 세 파일이 그 작업 공간의 행동에 반영되어야 할 때만 이 기능을 켜라고 안내합니다.
- [Side Chat](/guide/go-side-chat/)도 기능이 켜져 있으면 프로필 파일을 참고해 답합니다.

## 문제 해결

프로필에 적은 지침이 반영되지 않을 때 확인할 순서입니다.

1. **Settings > General**에서 설정이 켜져 있는지 확인합니다.
2. 파일이 현재 작업 공간의 루트에 있는지 확인합니다. 하위 폴더에 있으면 불러오지 않습니다.
3. 파일 이름이 정확히 `SOUL.md`, `IDENTITY.md`, `USER.md`인지 확인합니다.
4. 파일이 비어 있지 않은지 확인합니다.
5. 에이전트 지시나 프로젝트 지시가 의도적으로 우선하고 있는 것은 아닌지 확인합니다.

## 알아 둘 점

- 이 설정은 **Settings > General**에 있는 앱 전체 설정으로 문서에 적혀 있습니다. 작업 공간이나 에이전트마다 따로 켜고 끌 수 있는지는 공식 문서에 설명이 없습니다.
- 파일 이름의 대소문자를 구분하는지 문서는 따로 밝히지 않습니다. "정확히" 일치해야 한다고만 적으므로 대문자 표기를 그대로 따르는 것이 안전합니다.
