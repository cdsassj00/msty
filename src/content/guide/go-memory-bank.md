## 메모리가 필요한 이유

에이전트에게 같은 프로젝트를 여러 번 맡기다 보면 매번 같은 설명을 반복하게 됩니다. "보고서는 개조식으로", "이 폴더의 파일명 규칙은 이렇다" 같은 것들입니다. Go의 메모리는 이런 연속성을 위해 만들어졌습니다.

핵심은 두 가지를 나누는 것입니다. 지금 하고 있는 일의 상태와, 오래 남겨야 할 맥락입니다. 이렇게 나누면 대화는 현재 일에 집중하면서도 중요한 결정은 잃지 않습니다.

## 두 개의 층

| 층 | 성격 | 넣는 것 |
|---|---|---|
| **Working Brief** | 현재 작업을 위한 살아 있는 구조화된 상태 | 진행 중인 맥락 |
| **Memory Bank** | 변경 이력이 남는 오래가는 Memory Pack | 확정된 사실과 결정 |

Go는 대화 상태를 Working Brief에 계속 반영합니다. 문서는 Working Brief를 임시 보관 장소로 쓰고, 중요한 맥락만 골라 Memory Bank로 올리라고 안내합니다.

## 오래 보관할 만한 것

문서가 든 좋은 후보는 네 가지입니다.

- 프로젝트의 제약과 관례
- 확정된 설계 결정
- 바뀌지 않는 API 관련 전제
- 팀의 업무 방식 선호

대화 전체를 통째로 넣는 것은 피합니다. 간결한 요약이 실제 가치를 담고 있다면 그것으로 충분합니다. 문서는 오래가는 기억은 양보다 질이 중요하다고 강조합니다. 잘 고른 기억은 나중에 찾기 쉽고 소음이 적습니다.

예를 들어(필자가 든 예입니다) "주간 보고서는 A4 한 장, 개조식, 숫자는 전주 대비 증감과 함께 적는다"는 Memory Pack에 넣을 만한 내용입니다. 반면 "오늘 3번 표를 고치는 중"은 Working Brief에 머물 내용입니다.

## Memory Pack으로 할 수 있는 일

- Pack 만들기
- 이름 바꾸기, 태그 다시 달기
- 여러 Pack에 걸쳐 검색
- 복제, 보관(archive), 복원, 삭제
- 가져오기와 내보내기
- 변경 이력 살펴보기

중요한 결정이 바뀔 때는 변경 이력을 근거 기록으로 씁니다. 여러 사람이 함께 쓰는 작업 흐름에서 특히 유용합니다.

Memory Bank 화면을 여는 정확한 메뉴 위치와 가져오기·내보내기의 파일 형식은 공식 문서에 설명이 없습니다.

## Pack을 어디에 붙이는가

Pack 하나를 여러 대상에 붙일 수 있습니다.

- 대화
- 에이전트
- Playbook
- 예약 작업

보관 처리한 Pack은 복원해야 다시 붙일 수 있습니다.

문서는 어디에 붙일지 미리 계획하라고 합니다. 중요한 Pack은 필요한 곳에 붙이고, 관련 없는 맥락마다 복사본을 만들지 않습니다.

## 폴더 메모리와 Memory Inbox

Go는 사이드바 폴더의 **Memory Inbox**를 통해 폴더 단위 메모리를 지원합니다.

- 폴더마다 대화에서 배우기(learn-from-chats) 모드를 선택적으로 켤 수 있습니다.
- 그 폴더의 대화에서 재사용할 만한 기억 제안이 만들어질 수 있습니다.
- 제안은 종류별로 받아들이거나, 고치거나, 닫거나, 잊게 할 수 있습니다. 종류는 `Notes`, `Rules`, `Choices`, `To-dos`, `Links`입니다.
- 받아들인 폴더 메모리는 같은 폴더의 새 대화에서 자동으로 쓸 수 있습니다.

문서의 조언은 제안이 쌓이도록 두지 말고 정기적으로 검토하라는 것입니다.

폴더 중심 작업 흐름에는 폴더에 넣지 않은 대화를 자동 정리하는 옵션과, 폴더 메뉴에서 새 대화나 에이전트 대화를 쉽게 만드는 기능도 포함됩니다. 일이 실제로 이루어지는 곳과 기억의 맥락을 맞추기 위한 것입니다.

## Pulse와 함께 검토하기

[Pulse](/guide/go-pulse/)는 검토할 만한 것이 있을 때 폴더 메모리 후보와 학습 패턴을 카드로 띄울 수 있습니다. 이 카드는 자동으로 저장되는 기억이 아니라 의도적으로 검토하라는 알림입니다.

1. Pulse가 메모리 후보나 반복되는 패턴을 알려 주게 둡니다.
2. 근거가 된 폴더 메모리 항목이나 원래 대화를 확인합니다.
3. 받아들일지, 고칠지, 닫을지, 잊게 할지 직접 정합니다.

이렇게 하면 Memory Bank는 잘 고른 상태로 유지되면서도, 배울 만한 기회는 놓치지 않습니다.

## 메모리 전용 모델 배정

**Settings > Model Assignments**에서 `Memory` 항목에 전용 모델을 정할 수 있습니다. 정하지 않으면 현재 대화 모델 설정을 씁니다. 전용 모델이 유용한 경우는 다음과 같습니다.

- 메모리 처리 비용을 낮추고 싶을 때
- 요약 방식을 더 일정하게 유지하고 싶을 때
- 메모리와 실행을 따로 조정하고 싶을 때

주 대화 모델이 비싸거나 요약보다 코딩에 맞춰진 모델일 때 특히 쓸모가 있습니다. 배정 방법은 [모델 제공업체 설정](/guide/go-model-providers/)에 있습니다.

## 정리 습관

- 제목은 구체적이고 검색하기 쉽게 짓습니다.
- 태그는 범위를 좁게 답니다.
- 오래된 Pack은 주기적으로 솎아 냅니다.
- 작업 흐름을 크게 바꾸기 전에 변경 이력을 검토합니다.

문서는 매주 가볍게 한 번 정리하는 것으로 대개 충분하다고 적습니다.

## 관련 기능과의 구분

| 기능 | 무엇을 담는가 |
|---|---|
| Working Brief | 지금 작업의 상태 |
| Memory Pack | 여러 작업에 걸쳐 오래 쓰는 사실과 결정 |
| 폴더 메모리 | 한 폴더의 대화에서 배운 것. 그 폴더의 새 대화에 적용 |
| [작업 공간 프로필 파일](/guide/go-workspace-profile-files/) | 작업 공간 루트의 `SOUL.md`, `IDENTITY.md`, `USER.md`에 적어 둔 성격과 선호 |

작업 공간 프로필 파일 문서는 `MEMORY.md`를 불러오지 않는다고 밝히고, 오래가는 기억에는 Memory Bank를 쓰라고 안내합니다.

## 알아 둘 점

- Pack의 크기나 개수 한도는 공식 문서에 설명이 없습니다.
- 대화에서 배우기 모드의 기본값이 켜짐인지 꺼짐인지 문서는 밝히지 않습니다. "선택적"이라고만 적습니다.
