## 먼저 알아 둘 점: 아직 출시되지 않았습니다

Msty Stack은 2026-10-11 확인 기준으로 출시 전 제품입니다. 공식 사이트 첫 화면은 "Coming soon"이라고 표시하고, 제품 페이지는 "upcoming"이라고 적었습니다. 내려받을 수 있는 파일은 없고, 제품 페이지에는 회사 웹사이트와 이메일을 넣고 **Notify me**를 누르는 출시 알림 신청 양식만 있습니다.

출시 날짜는 사이트 어디에도 적혀 있지 않습니다. 요금 페이지도 출시 세부 사항이 정해지지 않았다고 밝힙니다. 따라서 이 글의 내용은 모두 "사이트가 이렇게 만들 계획이라고 밝힌 것"이며, 실제 제품은 달라질 수 있습니다.

## Stack은 무엇을 하려는 제품인가

공식 사이트는 Stack을 "Governed knowledge layer", 곧 관리되는 지식 계층이라고 부릅니다. 제품 페이지의 설명을 풀면 이렇습니다.

조직에는 규정집, 제품 설명서, 계약서 양식처럼 AI가 답할 때 근거로 삼아야 하는 자료가 있습니다. 지금은 사람마다, 앱마다 이 자료를 따로 올리고 따로 색인합니다. 그러면 누가 어느 버전을 쓰는지 알 수 없습니다. Stack은 승인된 자료를 버전이 붙은 Knowledge Stacks로 묶어 두고, 인증된 앱만 그 내용을 가져다 쓰게 하려는 제품입니다.

페이지는 Stack을 "API-first knowledge control plane"이라고도 표현합니다. 화면에서 사람이 쓰는 도구라기보다, 다른 앱이 API로 불러 쓰는 뒤쪽 계층이라는 뜻입니다. 또 지식을 특정 모델 하나에 묶지 않는다고 설명합니다.

## Studio의 Knowledge Stacks와 무엇이 다른가

이름이 비슷해서 헷갈리기 쉽습니다.

| 구분 | Studio의 Knowledge Stacks | Msty Stack |
|---|---|---|
| 상태 | 지금 사용 가능 | 출시 예정 |
| 쓰는 곳 | Studio 앱 안에서 대화할 때 | 여러 AI 앱이 API로 호출 |
| 관리 주체 | 사용자 개인 (팀 공유는 Enterprise) | 조직이 중앙에서 관리 |
| 버전 관리 | 제품 페이지에 설명 없음 | 변경마다 별도 버전으로 기록 |

지금 당장 내 문서를 근거로 답하게 하려면 Studio의 Knowledge Stacks를 쓰면 됩니다. Studio 소개는 [Msty Studio 자세히 보기](/guide/product-studio/)에 있습니다.

## 사이트가 밝힌 기능

제품 페이지에 나온 기능 여덟 가지입니다. 모두 계획 단계의 설명입니다.

| 기능 | 설명 |
|---|---|
| Versioned context | 조직의 자료를 버전이 붙은 Knowledge Stacks로 묶고, 지원되는 배포 환경 사이에서 옮길 수 있게 합니다 |
| Governed retrieval | 자료는 앱이 쓰기 전에 stack, bundle, catalog 단계를 명시적으로 거칩니다 |
| API first | 인증된 클라이언트에 제공하며, Nexus 또는 다른 승인된 추론 계층과 함께 씁니다 |
| Deployment choice | 관리형 클라우드, 온프레미스, 고객 소유 환경을 계획하고 있습니다 |
| Versioned stacks | 변경할 때마다 새 버전으로 기록하므로, 잘 돌아가는 버전을 덮어쓰지 않습니다 |
| Bundles & catalogs | 관련된 stack을 bundle로 묶고, 둘러볼 수 있는 catalog로 공개합니다 |
| Authenticated retrieval | 유효한 자격 증명을 가진 클라이언트에만 내용을 제공합니다 |
| Docker-deployable | 자체 컨테이너에서 실행합니다. 인스턴스 하나부터 관리형 클라우드까지 |

세 가지 용어를 정리하면 다음과 같습니다.

- **stack**: 자료 묶음 하나. 버전이 붙습니다.
- **bundle**: 관련된 stack 여러 개를 묶은 것.
- **catalog**: bundle을 찾아볼 수 있게 공개한 목록.

각 단계에서 누가 승인하는지, 어떤 파일 형식을 받는지, 검색 방식이 무엇인지는 사이트에 구체적인 설명이 없습니다.

## 어떤 업무를 염두에 둔 제품인가

사이트의 업종별 페이지들은 Stack을 "승인된 내부 자료를 묶어 두어, AI 작업 흐름이 매번 맥락을 새로 만들지 않고 가져다 쓰게 하는 것"으로 소개합니다. 예를 들어 법무팀이 표준 계약 조항집을 한 번 묶어 두면, 검토용 앱과 초안 작성용 앱이 같은 버전을 참조하는 식입니다.

다만 이는 출시 뒤의 사용 모습을 설명한 것이고, 지금은 쓸 수 없습니다. 업종별 설명은 [업종별 활용 방안](/guide/solutions-by-industry/)에 정리했습니다.

## 다른 제품과의 관계

제품 페이지는 Stack이 Nexus 또는 다른 승인된 추론 계층과 함께 쓰인다고 적었습니다. 역할을 나누면 이렇습니다.

- Nexus: 어떤 앱이 어떤 모델을 쓸 수 있는지 관리합니다.
- Stack: 그 앱이 어떤 자료를 근거로 삼을 수 있는지 관리합니다.

네 제품 전체의 관계는 [Msty 플랫폼 한눈에 보기](/guide/platform-overview/)에서 설명합니다.

## 요금

요금 페이지의 Stack 항목은 다음과 같습니다. 2026-10-11 확인 기준이며, 가격은 하나도 공개되지 않았습니다.

| 요금제 | 가격 | 사이트의 설명 |
|---|---|---|
| Preview | 공개 안 됨 (Coming soon) | 중앙에서 관리하는 Knowledge Stacks, 버전이 붙은 bundle과 catalog, 승인된 클라이언트용 API 접근, Nexus 또는 기존 추론 환경과 호환 |
| Teams | 문의 (계획 단계) | 팀이 관리하는 stack 수명 주기, 자료 공유 관리, 승인된 앱의 접근 통제 |
| Enterprise | 문의 | 배포 방식 선택, 인증된 클라이언트 접근, 지식 운영 관리 |

## 지금 할 수 있는 일

1. 제품 페이지에서 출시 알림을 신청합니다.
2. 조직에서 AI가 근거로 삼아야 할 자료가 무엇인지, 누가 승인하는지 목록을 만들어 둡니다. 어느 도구를 쓰든 필요한 준비입니다.
3. 당장 필요한 문서 근거 답변은 Studio의 Knowledge Stacks로 시작합니다.

출시 일정이나 가격을 근거로 예산과 계획을 세우는 것은 권하지 않습니다. 사이트에 날짜가 없기 때문입니다.
