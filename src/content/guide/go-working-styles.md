## Working Styles란

**Working Styles**(작업 방식)는 Go가 계획하고, 실행하고, 사용자에게 알리는 방식을 정하는 설정입니다. 속도, 꼼꼼함, 위험을 대하는 태도 사이의 균형을 조절하는 손잡이라고 보면 됩니다.

문서는 이것이 겉모습만 바꾸는 설정이 아니라고 강조합니다. 행동하기 전에 얼마나 확인하는지, 얼마나 과감하게 진행하는지, 사용자에게 얼마나 자세히 보고하는지가 달라집니다.

## 기본 제공 다섯 가지

| 방식 | 쓰는 경우 |
|---|---|
| `Balanced` | 일상적인 실행, 여러 성격이 섞인 업무 |
| `Careful` | 위험이 큰 변경, 더 강한 검증이 필요한 작업 |
| `Builder` | 구현 중심으로 빠르게 반복할 때 |
| `Support` | 사용자 지원, 운영 도움 업무 |
| `Reviewer` | 품질 검사, 버그 찾기, 회귀 점검 |

예를 들어(필자가 든 예입니다) 운영 서버 설정 파일을 고치는 에이전트에는 `Careful`을, 새 기능 초안을 빠르게 만들어 보는 에이전트에는 `Builder`를, 다른 사람이 쓴 문서나 코드를 검토하는 에이전트에는 `Reviewer`를 붙이는 식입니다.

문서의 조언 하나를 기억해 둘 만합니다. 어떤 작업에서 피할 수 있었던 위험이나 피할 수 있었던 지연이 반복된다면, 가장 먼저 다시 볼 설정이 작업 방식입니다.

## 작업 방식이 바꾸는 것

- 실행의 속도와 깊이
- 위험을 받아들이는 정도와 검증 동작
- 응답의 구조와 자세함
- 먼저 만들고 보는 태도인가, 먼저 검토하는 태도인가

문서는 작업 방식 선택을 실행 방식(Host/Container)이나 권한 범위를 고르는 것과 같은 급의 운영 통제로 다루라고 합니다.

각 방식이 구체적으로 어떤 단계를 더하거나 생략하는지는 공식 문서에 설명이 없습니다. 실제 차이는 같은 작업을 방식만 바꿔 돌려 보며 확인해야 합니다.

## 설정 위치와 상속

| 설정 | 위치 |
|---|---|
| 기본 방식 | **Settings > General** |
| 에이전트별 덮어쓰기 | 에이전트 설정 화면 |

에이전트에 덮어쓰기가 없으면 앱 기본 방식을 그대로 물려받습니다.

문서는 상속을 기본 정책으로 삼으라고 권합니다. 에이전트 단위로 덮어쓰는 것은 그 에이전트가 다르게 행동해야 할 분명하고 반복되는 이유가 있을 때로 한정합니다.

[Side Chat](/guide/go-side-chat/)도 선택된 작업 방식을 반영해 답합니다.

## 팀에 적용할 때

1. 대부분의 업무에 쓸 기본 방식 하나를 고릅니다.
2. 예외를 명시적으로 정합니다. 문서의 예는 운영 환경 변경에 `Careful`을 쓰는 것입니다.
3. 전문화된 에이전트에만 덮어쓰기를 적용합니다.
4. 실제 업무에서 나온 반응을 보고 기본값을 다시 검토합니다.

작업 방식 규칙을 명시해 둔 팀은 결과가 더 예측 가능하고, 사람이 그때그때 손으로 조정하는 일이 줄어든다는 것이 문서의 설명입니다.

## 처음 시작하는 사람을 위한 권장값

Setup 문서의 제안입니다.

- 앱 기본값은 `Balanced`
- 위험이 큰 에이전트만 `Careful`

처음에는 덮어쓰기를 적게 둡니다. 에이전트마다 방식이 다르면 초기 검증에서 동작을 비교하기 어렵습니다.

## 알아 둘 점

- 사용자가 직접 새 작업 방식을 만들 수 있는지는 이 문서 페이지에 설명이 없습니다. 문서는 "현재 기본 제공" 방식 다섯 가지만 나열합니다.
- 작업 방식은 안내 성격의 설정입니다. 폴더·네트워크 접근 같은 강제 통제는 [보안 설정](/guide/go-security/)에서 따로 정합니다.
