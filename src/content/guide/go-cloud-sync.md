## Cloud Sync란

**Cloud Sync**는 여러 기기에서 Go의 상태를 같게 유지하는 기능입니다. 암호화 보호가 작업 흐름에 들어 있습니다.

문서는 첫머리에서 주의를 줍니다. 동기화 방향을 어떻게 고르느냐에 따라 기존 상태가 영향을 받을 수 있으므로 설정을 신중하게 다뤄야 합니다.

설정 위치는 **Settings > Cloud**입니다.

## 이용 조건

Cloud Sync는 접근이 제한된 기능입니다. 초대받은 계정이라면 로그인해서 설정을 이어 갑니다.

계정에 접근 권한이 없다면 로컬 방식으로 계속 운영합니다. 문서는 이 경우 기기 간에 필요한 작업 흐름을 적어 두었다가 나중에 도입할 때 쓰라고 권합니다.

초대제 Android 접근은 기기 간 기능을 넓혀 가는 과정의 일부로, 조건에 맞는 계정에 열릴 수 있습니다.

초대를 받는 방법과 요금은 이 문서 페이지에 설명이 없습니다. 요금 전반은 [요금제 자세히 보기](/guide/pricing/)를 참고합니다.

## 보안 구조

문서가 밝힌 것은 세 가지입니다.

- 종단 간 암호화(End-to-end encrypted)
- 저장 시 암호화(Encrypted at rest)
- 계정 복구에는 복구 키가 필요함

복구 키는 안전한 인증 정보 보관 체계에 저장합니다. 문서는 복구 키 관리를 선택적인 설정 단계가 아니라 업무 연속성의 필수 조건으로 다루라고 강조합니다.

복구 키를 잃어버렸을 때 어떻게 되는지는 공식 문서에 직접 적혀 있지 않습니다. 다만 계정 복구에 복구 키가 "필요하다"고 적혀 있으므로, 잃어버리지 않도록 설정 즉시 보관해야 합니다.

## 첫 기기 설정

첫 기기에서 동기화를 켤 때는 어느 쪽을 기준으로 삼을지 의도적으로 고릅니다.

| 선택 | 뜻 |
|---|---|
| Use this device as source | 이 기기를 기준으로 삼습니다 |
| Restore from existing cloud state | 이미 있는 클라우드 상태에서 복원합니다 |
| Merge | 합칩니다(지원되는 경우) |

확신이 없으면 멈추고 어느 쪽 데이터가 기준인지 먼저 확인합니다. 문서는 방향을 잘못 고르는 것이 실수로 상태를 덮어쓰는 가장 흔한 원인 가운데 하나라고 적습니다.

예를 들어(필자가 든 예입니다) 석 달 동안 에이전트와 Playbook을 만들어 온 사무실 컴퓨터에서 처음 동기화를 켠다면 이 기기를 기준으로 삼는 것이 맞습니다. 여기서 클라우드 복원을 고르면 의도와 다른 결과가 나올 수 있습니다.

## 다른 기기 추가

1. 새 기기에서 로그인합니다.
2. 요구되는 대로 기기를 승인하거나 신뢰 처리합니다.
3. 동기화 방향을 의도적으로 고릅니다.
4. 첫 동기화를 실행하고 주요 항목을 검증합니다.

첫 동기화 직후, 평소처럼 쓰기 전에 다음을 확인합니다.

- 최근 대화
- 에이전트 설정
- 중요한 설정
- 동기화된 에이전트가 새 기기에서 기대한 대로 보이는지

## 기기 관리

Cloud Sync에 포함된 관리 기능입니다.

- 신뢰하는 기기 목록
- 승인 대기 상태
- 취소·제거 동작
- 현재 기기를 표시하는 `This Mac` 표시

신뢰 기기 목록은 정기적으로 검토합니다. 특히 기기를 바꾸었거나 담당자가 바뀐 뒤에 확인합니다.

문서에는 현재 기기 표시가 `This Mac`으로만 적혀 있습니다. Windows나 Linux에서 어떻게 표시되는지는 공식 문서에 설명이 없습니다.

## 운영 동작

| 동작 | 설명 |
|---|---|
| `Sync Now` | 지금 동기화합니다 |
| Sign out of Cloud Sync | Cloud Sync에서 로그아웃합니다 |
| Start over | 연결된 클라우드 쪽 상태를 초기화합니다 |

`Start over`는 영향이 큰 동작입니다. 복구 경로와 기준으로 삼을 상태를 분명히 확인한 뒤에만 씁니다.

## Msty Go 휴대전화 연결

**Msty Go**를 통한 전화 접근은 Cloud 설정 영역에서 관리합니다.

| 조건·동작 | 내용 |
|---|---|
| 계정 | 모바일이 켜진 클라우드 계정이 필요합니다 |
| 선행 조건 | 휴대전화를 연결하기 전에 데스크톱의 Data Sync 설정을 마쳐야 합니다 |
| 연결 방식 | 수명이 짧은 QR 코드와 일회용 연결 코드를 씁니다 |
| 해제 | 연결된 휴대전화는 같은 설정 영역에서 취소하거나 제거합니다 |
| 재연결 | 데스크톱 연결을 다시 시도할 때 재연결 컨트롤이 눈에 보이는 반응을 줍니다 |

문서는 기기 승인, 동기화 상태, 경로 프리셋을 기기를 추가할 때마다 함께 검증해야 모바일 연결이 가장 안정적이라고 설명합니다. 연결한 휴대전화로 메시지를 보내는 경로 설정은 [채널](/guide/go-channels/)에서 다룹니다.

## 안전 지침

일부 동기화 방향은 대상 쪽 데이터를 덮어쓸 수 있습니다. 설정을 확정하기 전에 방향을 확인합니다.

팀이라면 Cloud Sync 복구와 기기 추가에 대한 짧은 절차서를 두라고 문서는 권합니다. 이런 선택이 매번 같은 방식으로 이루어지고 나중에 확인할 수 있게 하기 위해서입니다.

절차서에 넣을 만한 항목은 다음과 같습니다(문서의 지침을 바탕으로 필자가 정리한 것입니다).

1. 기준 기기가 어느 것인가
2. 복구 키를 어디에 보관하고 누가 꺼낼 수 있는가
3. 새 기기를 추가할 때 고를 방향
4. 첫 동기화 뒤 확인할 항목
5. 기기를 교체하거나 담당자가 바뀔 때 신뢰 기기 목록을 정리하는 사람

## 언제 켜는가

Setup 문서는 Cloud Sync를 2단계 설정으로 분류합니다. 기기 간 연속성이 실제로 필요하고, 복구 키를 어떻게 다룰지 팀에 계획이 있을 때만 켭니다. 로컬 실행이 아직 안정되지 않았다면 로컬에 머물며 검증을 계속합니다.

## 알아 둘 점

- 정확히 어떤 데이터가 동기화되는지의 전체 목록은 공식 문서에 설명이 없습니다. 문서는 대화, 에이전트 설정, 중요한 설정을 확인 대상으로 들 뿐입니다.
- 클라우드 저장 위치(지역)와 보관 기간도 이 문서 페이지에 적혀 있지 않습니다.
- 동기화가 자동으로 이루어지는 주기도 문서에 설명이 없습니다.
