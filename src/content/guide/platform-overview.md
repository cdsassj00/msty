## 공식 사이트의 구성

Msty 공식 사이트(msty.ai)는 CloudStack, LLC가 운영합니다. 사이트 첫 화면은 Msty를 개인 작업 공간, 범위가 정해진 에이전트, 모델 선택, 지식 관리를 하나로 잇는 시스템으로 소개합니다. 대상은 개인, 팀, 조직입니다.

사이트 상단 메뉴는 다음과 같이 나뉩니다.

| 메뉴 | 들어 있는 것 |
|---|---|
| **Products** | 플랫폼 소개, Studio, Go, Nexus, Stack |
| **Solutions** | Education, Legal, Operations, Healthcare, Research, Regulated teams |
| **Resources** | Blog, Whitepapers, Studio docs, Go docs, Nexus docs |
| **About**, **Pricing**, **Security** | 회사 소개, 요금, 보안 설명 |
| **Talk to us** | 문의 양식 |

이 글은 **Products** 메뉴의 플랫폼 소개 페이지를 바탕으로 네 제품의 관계를 설명합니다.

## 네 가지 제품과 역할

플랫폼 페이지는 네 제품에 번호와 한 단어짜리 역할을 붙여 놓았습니다.

| 번호 | 제품 | 사이트의 한 줄 설명 | 역할 | 상태 |
|---|---|---|---|---|
| 01 | Studio | Private AI workspace | Work (일하는 곳) | 내려받아 사용 가능 |
| 02 | Go | Bounded AI agents | Direct (일을 시키는 곳) | 무료 베타 |
| 03 | Nexus | AI control center | Connect (연결하는 곳) | 내려받아 사용 가능 |
| 04 | Stack | Governed knowledge layer | Ground (근거를 대는 곳) | 출시 예정 |

각 제품이 맡는 일을 풀어 쓰면 이렇습니다.

- **Studio**: 모델과 대화하고, 자료를 정리하고, 이미지 같은 미디어를 만들고, 프롬프트를 다시 쓰는 작업 공간입니다. 사람이 직접 앉아서 쓰는 화면입니다.
- **Go**: 폴더나 프로젝트처럼 범위를 정해 준 에이전트가 실제 작업을 수행합니다. 사용자는 단계마다 검토하고, 데스크톱이나 모바일에서 지시합니다.
- **Nexus**: 로컬 실행 엔진, 온라인 제공업체, API 키, 정책, 앱 토큰, 사용량을 한곳에서 관리하는 로컬 제어 센터입니다. 여러 AI 앱이 모델에 접근할 때 지나가는 관문(게이트웨이) 역할을 합니다.
- **Stack**: 승인된 자료를 버전이 붙은 Knowledge Stacks로 묶어, 승인된 AI 앱이 다시 쓸 수 있게 합니다. 아직 출시되지 않았습니다.

## 제품이 이어지는 방식

플랫폼 페이지의 설명은 두 가지로 요약됩니다.

첫째, 각 제품은 따로 써도 됩니다. Studio만 설치해서 개인 작업에 쓰는 것이 가장 흔한 시작입니다.

둘째, 함께 쓰면 "모델에 접근하는 일"부터 "실제 업무"까지가 한 줄로 이어집니다. 사이트가 설명하는 분담은 다음과 같습니다.

| 단계 | 맡는 제품 | 하는 일 |
|---|---|---|
| 모델 접근과 통제 | Nexus | 어떤 앱이 어떤 모델과 키를 쓸 수 있는지 정하고 사용량을 봅니다 |
| 신뢰할 수 있는 지식 | Stack | 승인된 자료를 버전별로 묶어 제공합니다 |
| 사람의 작업 | Studio | 대화, 문서 근거 답변, 프롬프트 재사용 |
| 에이전트 작업 | Go | 범위가 정해진 작업을 실행하고 검토를 받습니다 |

업무 예를 하나 들어 보겠습니다. 어느 팀이 사내 규정집을 근거로 답하는 AI를 쓰고 싶다고 합시다. 팀원은 Studio에서 규정집을 Knowledge Stacks로 만들어 질문합니다. 반복되는 보고서 정리는 Go 에이전트에게 특정 폴더만 열어 주고 맡깁니다. 여러 사람이 쓰기 시작하면 Nexus를 두어 API 키를 한곳에 보관하고 앱마다 토큰을 따로 발급합니다. 규정집을 조직 전체가 같은 버전으로 써야 하는 단계가 되면 Stack이 그 자리를 맡는다는 것이 사이트의 그림입니다. 다만 Stack은 아직 나오지 않았으므로 지금은 앞의 세 가지로 구성해야 합니다.

## 배포 방식 선택

플랫폼 페이지는 배포 방식을 한 가지로 정해 두지 않습니다. 사이트가 나열한 선택지는 네 가지입니다.

1. 데스크톱 앱으로 시작한다.
2. 승인된 클라우드 모델을 연결한다.
3. 로컬에서 모델을 실행한다.
4. 고객이 소유한 환경에 배포하는 계획을 세운다.

구체적인 배포 구성도나 서버 요구 사양은 플랫폼 페이지에 없습니다. 제품별 조건은 각 제품 페이지와 문서에서 확인해야 합니다.

## 기업 도입 경로

기업용 소개 페이지(Enterprise overview)는 전사 도입 선언보다 작은 시범 운영(pilot)을 권합니다. 페이지가 제시하는 순서는 세 단계입니다.

1. **범위 정하기**: 팀, 업무, 데이터, 성공 기준을 고릅니다.
2. **시스템 구성하기**: 승인된 모델, 지식, 팀 통제 기능을 연결합니다.
3. **실제 업무로 배우기**: 그 업무를 실제로 하는 사람들과 함께 시범 운영합니다.

같은 페이지는 네 가지 원칙도 적어 두었습니다. 승인된 모델을 쓰되 제공업체 접근과 자격 증명은 한곳에 둔다, 조직의 지식은 경계를 두고 쓴다, 측정할 수 있는 업무 하나로 시작한다, 필요가 분명해질 때 제품과 배포 방식을 더한다는 내용입니다.

이 페이지에는 SSO, 감사 로그, 저장 위치, 인증 현황 같은 세부 사항이 적혀 있지 않습니다. 그 내용은 보안 페이지와 Studio 문서의 Enterprise 항목에 있으며, [보안과 거버넌스](/guide/security-governance/) 글에서 정리했습니다.
