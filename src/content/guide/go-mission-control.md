## Mission Control이란

**Mission Control**은 복잡한 작업을 위한 상황실입니다. 여러 에이전트가 움직이는 실행, 대기 중인 승인, 진행 상태, 그리고 결과를 대화로 되돌려 주는 인계를 추적합니다.

한 번의 답으로 끝내기에는 복잡하고, 여러 갈래를 조율하면서 진행 상황을 눈으로 보고 싶은 작업에 가장 쓸모가 있습니다.

## 언제 쓰는가

요청이 다음 가운데 하나에 해당하면 Mission Control이 도움이 됩니다.

- 역할이 분명한 도우미 여럿이 동시에 일하면 좋은 작업
- 새 맥락에서 하는 비평이나 검증이 필요한 작업
- 도구 사용 중에 명시적인 승인 지점이 필요한 작업
- 진행 중인 작업의 상태를 한곳에서 검토하고 싶을 때

예를 들어(필자가 든 예입니다) 분기 보고서를 만든다고 하면, 한 도우미는 매출 자료를 정리하고, 다른 도우미는 고객 문의 기록을 요약하고, 세 번째 도우미는 앞의 두 결과를 처음 보는 눈으로 검토하게 할 수 있습니다. 사용자는 각 도우미의 상태와 승인 요청을 한 화면에서 봅니다.

## 두 가지 인계를 구분하기

Go에는 성격이 다른 인계가 두 가지 있습니다. 이름이 비슷해 헷갈리기 쉽습니다.

| 인계 | 내용 | 쓰는 경우 |
|---|---|---|
| **Mission helper handoff** | 하위 에이전트(도우미)가 맡은 부분의 결과를 Mission Control을 통해 돌려줍니다 | 동시에 진행되는 실행을 눈으로 보며 관리해야 할 때 |
| **Local chat-to-agent handoff** | 기존 로컬 대화를 에이전트에 붙여, 에이전트가 기존 대화 기록·작업 공간·폴더 접근을 이어받아 계속합니다 | 로컬 대화가 에이전트가 맡을 작업으로 자랐을 때 |

두 번째 인계는 [에이전트 만들기와 관리](/guide/go-agents/)에서 다룹니다.

## 기본 흐름

1. 대화에서 작업을 시작합니다.
2. 필요한 만큼 역할이 분명한 도우미(하위 에이전트)를 띄웁니다.
3. Mission Control에서 진행 상황과 막힌 지점을 봅니다.
4. 승인을 처리하고 결과물을 검토합니다.
5. 최종 결과를 주 대화로 합칩니다.

## 작업 상태

작업 상태는 보통 다음 순서로 바뀝니다.

| 상태 | 뜻 |
|---|---|
| `Working` | 진행 중 |
| `Needs you` | 사용자의 개입이 필요함 |
| `Ready to review` | 검토를 기다림 |
| `Done` | 끝남 |

상태를 보면 어디에 개입해야 하고, 무엇이 검토 대기이고, 무엇이 내보낼 준비가 되었는지 빠르게 가려낼 수 있습니다. 표의 뜻풀이는 상태 이름과 문서의 설명을 바탕으로 정리한 것입니다.

## Task Force 프리셋

**Settings > Task Force**에서 자주 쓰는 역할을 도우미 프리셋으로 만들어 둡니다. 프리셋마다 정할 수 있는 것은 세 가지입니다.

| 항목 | 내용 |
|---|---|
| 역할과 목표 | 도우미가 누구이고 무엇을 이루어야 하는가 |
| 도구 정책 경계 | 어떤 도구까지 쓸 수 있는가 |
| 출력 계약 | 결과를 어떤 형태로 돌려줘야 하는가 |

프리셋을 써 두면 반복되는 작업에서 여러 에이전트의 동작이 같게 유지됩니다. 문서는 프리셋을 "재사용할 수 있는 관리 규칙"으로 보라고 합니다. 매번 다르게 쓰인 지시로 동작이 흔들리는 일이 줄고, 도우미가 어떻게 행동했는지 나중에 확인하기 쉬워집니다.

컨테이너에서 도우미를 쓰는 경우에는 위임된 작업이 모두 같은 도구를 갖도록 환경 구성을 명시해 두라는 조언이 에이전트 문서에 있습니다.

## 승인과 검토

Mission Control은 실행 중인 도우미가 올린 권한 요청을 모아서 보여 줍니다.

- 하나씩 승인하거나 거부합니다.
- 적절한 경우 대기 중인 요청을 묶어서 처리합니다.
- 결정이 내려질 때까지 막힌 작업이 계속 보이게 둡니다.

승인 기록은 권한을 조정하는 근거로 씁니다. 중요한 안전장치는 남겨 두고, 반복되는 불필요한 요청만 줄이는 방향입니다. 승인의 기준이 되는 설정은 [보안 설정](/guide/go-security/)에 있습니다.

## Peek-a-Boo 미리보기

사이드바의 대화나 작업 항목에 마우스를 올리면 미리보기가 뜹니다. 문서는 이를 "Peek-a-Boo"라고 부릅니다.

- 화면을 바꾸지 않고 최근 작업 활동을 확인합니다.
- 간단한 승인은 미리보기 안에서 바로 처리합니다.
- 움직이는 작업과 멈춰 있는 작업을 빠르게 가려냅니다.

여러 작업이 동시에 돌아가서 화면을 오가는 부담이 커질 때 가장 유용합니다.

## Pulse와는 다르다

[Pulse](/guide/go-pulse/) 문서는 Pulse가 Mission Control이 아니라고 명시합니다. Pulse는 최근 작업을 훑어 주의가 필요한 것을 알려 주는 브리핑이고, Mission Control은 지금 실행 중인 작업을 추적하고 승인하는 곳입니다.

## 알아 둘 점

- 동시에 띄울 수 있는 도우미 수의 한도는 공식 문서에 설명이 없습니다.
- Mission Control 화면을 여는 정확한 메뉴 위치는 이 문서 페이지에 적혀 있지 않습니다.
- 도우미를 Go가 스스로 띄우는지, 사용자가 지시해야 하는지의 조건도 문서에 설명이 없습니다. 문서는 "필요한 만큼 도우미를 띄운다"고만 적습니다.
