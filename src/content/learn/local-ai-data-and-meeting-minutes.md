## 이 글에서 다루는 세 가지

문서 초안과 요약 다음으로 로컬 모델을 많이 쓰게 되는 일은 표와 숫자, 여러 건의 글, 녹음 파일입니다. 교육과정 보드에서 이 일들은 폐쇄망에서도 되거나 반입 후 쓸 수 있는 것으로 표시되어 있습니다.

| 일 | 방법 | 필요한 것 |
|---|---|---|
| 엑셀 수식·정제 방법 받기 | 대화창에서 묻기 | 로컬 대화창 |
| 민원·설문 의견 대량 분류 | AI가 짜 준 코드 실행 | Python, Ollama, 언어 모델 |
| 회의 녹음을 회의록으로 | 전사 모델과 언어 모델 잇기 | 전사 모델(Whisper), 언어 모델 |

뒤로 갈수록 준비할 것이 늘어납니다. 첫 번째는 대화창만 있으면 됩니다.

## 1. 엑셀 일은 데이터가 아니라 구조를 알려 줍니다

보드의 "AI와 함께 쓰는 Excel" 모듈은 시트 구조를 설명해 수식·정제·피벗·차트 방법을 AI에게 묻고, 처리는 Excel에서 직접 하는 방식입니다. 표의 내용을 넣지 않아도 되므로 개인정보가 든 명단도 다룰 수 있습니다.

```text
엑셀 시트 구조를 설명하겠습니다.
- A열: 접수일 (2026-03-05 형식)
- B열: 부서명
- C열: 처리 상태 (접수, 처리중, 완료)
- D열: 금액
2행부터 데이터가 있고 약 3,000행입니다.

부서별로 "완료" 상태인 건의 금액 합계를 구하는 수식을 알려 주세요.
수식이 무엇을 하는지 한 줄씩 설명해 주세요.
```

모듈의 다른 실습 항목도 같은 방식으로 묻습니다.

- 수식 설명 받기와 `#N/A`·`#VALUE!` 원인 찾기
- 주소·날짜·코드처럼 제각각인 값 정제하기
- 두 명단을 비교해 누락·중복 찾기
- 기준·낙관·보수 시나리오 표 계산

작은 모델은 수식의 괄호나 인수 순서를 틀리는 일이 있습니다. 받은 수식은 답을 아는 몇 행으로 먼저 확인합니다. 오류가 나면 오류 메시지를 그대로 붙여 넣고 다시 묻습니다.

통계표를 읽고 보고 문장을 쓰는 일도 대화창에서 됩니다. 보드는 "전년 대비·비중·증감률 문장 쓰기"와 함께 "보고 문장의 수치 재검산"을 반드시 붙여 둡니다. 모델이 쓴 증감률은 직접 다시 계산합니다.

파일을 훑어보는 일은 모델 없이도 됩니다. [실습](/lab/)의 "CSV 자동 분석기"와 "파일에 바로 SQL 묻기"는 파일을 기기 밖으로 내보내지 않고 브라우저 안에서 처리합니다.

## 2. 의견 수천 건 분류하기

대화창에 한 건씩 붙여 넣어 분류할 수 있지만 수백 건을 넘으면 어렵습니다. 보드의 "AI 모델로 대량 텍스트 분석" 모듈은 AI가 준 Python 코드로 모델에 한 건씩 보내 분류·요약·쟁점을 뽑습니다. 외부망에서는 API로, 비공개 자료와 폐쇄망에서는 로컬 모델로 같은 코드를 쓴다고 설명합니다.

### 순서

1. **분류 기준을 먼저 정합니다.** 유형 이름과 판단 기준을 표로 적습니다. 어느 유형에도 맞지 않을 때 넣을 "기타"를 둡니다.
2. **표본으로 정확도를 봅니다.** 표본 몇십 건을 사람이 먼저 분류해 두고, 모델의 결과와 비교합니다.
3. **기준을 고칩니다.** 자주 틀리는 유형은 기준 문장이 모호한 경우가 많습니다. 예시를 덧붙입니다.
4. **전체를 돌립니다.** 건수가 많으면 시간이 걸립니다.
5. **결과를 Excel로 내보냅니다.** 유형별 건수와 대표 사례를 함께 뽑습니다.
6. **기준을 바꿨다면 전체를 다시 분류해 결과를 비교합니다.**

### 코드를 받을 때 줄 지시문

용어 사전의 "AI에게 이렇게 말하기" 문장을 모으면 지시문이 됩니다.

```text
Excel 파일의 "의견" 열을 한 건씩 읽어 유형을 분류하는 Python 코드를 만들어 주세요.
- Ollama에 설치한 모델을 쓰도록 만들고, 모델 이름은 설정 파일에서 바꿀 수 있게 해 주세요.
- 모델에게는 결과를 설명 없이 JSON으로만 출력하게 하고, 필드 이름과 형식을 먼저 정해 주세요.
- 파싱이 실패한 입력은 건너뛰지 말고 목록으로 따로 모아 보여 주세요.
- 결과는 원본 옆에 "유형"과 "판단 근거" 열을 붙여 새 Excel 파일로 저장해 주세요.
- 필요한 라이브러리와 실행 명령을 순서대로 알려 주세요.

분류 기준은 아래와 같습니다.
[기준 표 붙여넣기]
```

코드는 외부망 PC에서 공개 표본으로 만들어 시험한 뒤 폐쇄망으로 옮기는 편이 수월합니다. 이때 Python 설치 파일과 라이브러리도 함께 반입해야 합니다. 공공데이터 CSV를 읽다가 한글이 깨지면 인코딩 문제입니다. "파일 인코딩을 자동으로 판별하고, 결과는 UTF-8(BOM 포함)로 저장해 엑셀에서 깨지지 않게 해 주세요"라고 요청합니다.

### 결과를 믿어도 되는지

보드는 문서 일괄 처리 모듈에서 "결과 표본 10건을 원문과 대조"를 실습으로 둡니다. 전체를 다 볼 수 없으니 표본을 뽑아 확인하고, 틀린 비율이 높으면 기준을 고쳐 다시 돌립니다. "기타"로 분류된 건과 판단 근거가 비어 있는 건은 사람이 따로 봅니다.

## 3. 회의 녹음을 회의록으로

외부망에서는 전사 서비스에 녹음을 올리면 끝나지만, 비공개 회의 녹음은 올릴 수 없습니다. 보드의 "폐쇄망 회의록·문서 요약 파이프라인" 모듈은 로컬 전사 모델과 로컬 언어 모델을 이어 인터넷 없이 같은 일을 합니다.

### 두 단계로 나뉩니다

| 단계 | 하는 일 | 쓰는 모델 |
|---|---|---|
| 전사 | 음성을 글로 바꿉니다 | 전사 모델 (Whisper) |
| 정리 | 전사본을 요약하고 결정사항을 뽑습니다 | 언어 모델 |

전사만 먼저 해 보려면 [실습](/lab/)의 "인터넷 없는 받아쓰기"를 엽니다. 녹음하거나 음성 파일을 넣으면 기기 안에서 글자로 바꾸고, 텍스트나 자막 파일로 저장합니다. 처음에 모델을 내려받으므로 인터넷이 되는 PC에서 해 봅니다.

### 전사본을 정리하는 프롬프트

바이브코딩 시나리오 자료는 회의록을 네 부분으로 요약하게 합니다.

```text
아래는 회의 녹음을 글로 옮긴 전사본입니다. 다음 네 부분으로 회의록을 만들어 주세요.
1. 회의 개요: 일시, 장소, 참석자, 주요 안건
2. 안건별 논의 내용: 쟁점과 참석자별 의견
3. 최종 결정 사항
4. 향후 조치 계획: 담당자와 완료 목표일

전사본에 없는 내용은 쓰지 않습니다.
잘못 받아쓴 것으로 보이는 단어는 고치지 말고 [확인 필요]로 표시해 주세요.

[전사본 붙여넣기]
```

전사본이 길면 한 번에 들어가지 않습니다. 안건이나 시간 단위로 나눠 요약한 뒤 합칩니다.

### 자동화까지 간다면

모듈의 실습 항목은 구축 순서이기도 합니다.

1. 로컬 Whisper 모델을 반입하고 전사 품질을 비교합니다.
2. 전사본을 로컬 언어 모델로 요약하고 조치사항을 뽑습니다.
3. 회의록을 HWPX 서식으로 출력합니다.
4. 폴더에 녹음 파일을 넣으면 자동으로 처리되게 합니다.
5. 저사양 PC라면 경량 모델을 고릅니다.
6. 처리 기록과 원본 보관 규칙을 정합니다.

6번은 빠뜨리기 쉽습니다. 녹음 원본, 전사본, 회의록이 PC에 모두 남으므로 누가 언제까지 보관하고 지울지 정해 둡니다.

### 전사본에서 확인할 것

- 사람 이름, 기관명, 사업명 같은 고유명사
- 금액, 날짜, 건수 같은 숫자
- 여러 사람이 동시에 말한 구간
- 누가 말했는지. 발언자 구분은 틀릴 수 있으므로 결정사항의 담당자는 참석자에게 확인합니다.
